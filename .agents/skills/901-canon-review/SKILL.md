# 901 — Canon 与连续性审查

**任务**：对一组具体事实主张给出带证据的审查结论。此 Skill **不创作人物与剧情、不批准新正史、不自动修改权威文件**。

## 何时运行
- 需要判断设定是否有原团依据，或草案能否与既有 901 世界兼容。
- 处理重开起点、新旧时间线、人物认知、重大秘密及跨作品角色的继承范围。
- 在人物深化、剧情规划、社会设定扩写后，针对 **影响原有事实的部分**进行审核。
- **不运行**：普通 HP/技能计算、单纯写作润色、界面制作、酒馆条目打包、无事实修改的日常游玩。

## 输入与冷启动
1. 先读取实际仓库 `AGENTS.md`、项目状态和 Approved Canon 索引；检查是否有未批准的 `HOLD` 或候选补丁。只使用仓库中**实际存在**的路径，不推测命名与目录。
2. 明确目标：文件、角色/势力 ID、变更范围、所属时间线、所需判断；以最小相关材料为搜索范围。原团记录是证据材料，但需要区分记录里的**角色陈述**与叙事层确认的事实。
3. 为每项待审事实保留可核对的证据定位：真实文件路径＋行号/记录 ID/消息编号/可靠章节位置。无法定位的证据写 `NEEDS_SOURCE`，不得伪造引用。
4. 如资料缺失但只需检查文件格式，完成可验证部分；如缺失阻止事实判断，返回 `HOLD`，说明缺什么。

## 审查流程
1. **逐条切分**：把“某人发动战争，是因为报复父亲”切成行动事实与动机解释两个主张。分别评审，不以整段文字一次性放行。
2. **标注来源**：`APPROVED_901`、`ORIGINAL_RECORD`、`SOURCE_WORK_ONLY`、`INFERENCE`、`NEW_901`、`UNKNOWN`；同一个主张可有多条独立证据。分类规则详见 [证据与时间线](references/evidence-and-timeline.md)。
3. **检查时间线**：先核实重开切入点与继承范围，再标为 `PRE_CUT_HISTORY`、`OLD_POST_CUT_REFERENCE` 或 `NEW_TIMELINE`，另记具体 `time_ref`。时间分类只表示主张适用的故事线与时间范围，**不代表**已获批准或已经发生；这由 `content_state` 与主张内容分别说明。旧团后续不自动变成重开后的必然事件。
4. **检查改编**：对已有作品人物按字段核对身份、人格、关系、能力、历史与移植方式；本土化与穿越分开。参阅 [跨作品映射](references/adaptation-protocol.md)。
5. **检查冲突**：人物身份与战力、地区与政治结构、时间先后、行动可行性、知情范围、秘密与已展现证据、玩家自主权。输出具体矛盾对：`既有事实 → 新主张 → 无法同时成立的原因`。
6. **决定结果**：对每个主张给出 `PASS`（有据且相容）/ `REVISE`（需改写）/ `HOLD`（缺关键证据或无法裁决）。`PASS` **只表示通过审查**，不等于获得批准写入正史。参阅 [结论与交接](references/review-and-handoff.md)。
7. **交付报告**：按 [报告模板](assets/review-report.yaml) 输出；注明被查来源、每项决议、修改建议、受影响文件和仍需人工确认的权限。报告包含不同状态的主张时，在相应 `claim` 记录自己的 `content_state_before/after`，不可只依赖报告级状态。默认写入非权威草案/报告位置，不直接改动 Canon。

## 必须遵守的边界
- 原始团记录**可能未提供**某个反派的动机；未知就保留未知，不能把 AI 补写说成原始 GM 的设定。
- 来源作品人物的过去、关系、力量或势力**不自动全部**继承至 901；未核准移植范围的字段保持未定。
- 已在新时间线发生、对外产生证据或后果的事实不能为了剧情反转而被静默重写。人物可因新事件改变立场，但变化须有记录。
- 不代替御临风选择行动、台词、内心和最终胜负。
- 审核结果与内容状态分开：`DRAFT`、`ELIGIBLE`、`ESTABLISHED`、`APPROVED_CANON` 依项目实际数据结构解释；不能靠本 Skill 自动升级。
- 对冲突给出最小修订方案；既有 Canon 本身存在歧义时，列出竞争解释并 `HOLD`，不要擅自统一。
