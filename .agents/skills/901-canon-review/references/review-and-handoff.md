# 审查结论、权限与交接

## 独立的两个字段
- `review_decision`: `PASS` / `REVISE` / `HOLD`。表示审查结果。
- `content_state`: `DRAFT` / `ELIGIBLE` / `ESTABLISHED` / `APPROVED_CANON`。表示内容在项目中的状态。实际项目若已有命名，写出映射，不强行迁移。
- `timeline_scope` 和 `time_ref` 只表示所述内容所属的故事线与时间，不能代替 `content_state`；明确发生在切入点之前的原创草案仍可标 `PRE_CUT_HISTORY` + `DRAFT`。
- 同一报告中若既包含已发生事实又包含未定幕后方案，报告级 `content_state_before/after` 只作默认值；**混合状态须在逐条 `claim` 中覆盖**，不能将全部主张视为同一状态。

## 必要情形
- `PASS`：证据可定位，时间线明确，未发现重大冲突；并**不**自动写进 Canon。
- `REVISE`：至少一个可复现矛盾、有更保守改法；给出最小编辑建议，保留未受影响部分。
- `HOLD`：缺失对关键主张不可替代的证据，或现有资料彼此矛盾且无法据授权规则裁决。添加 `NEEDS_SOURCE` 列出尚缺记录。
- 草案中原创部分可以通过 **兼容性** 检查，即使没有任何原团出处；只能标 `NEW_901`，绝不可写“原团已确认”。

## 高影响设定的升级门槛
以下更改即便通过兼容性审查，也需按项目批准策略处理：原团已经确立的历史、重要人物身份、重大秘密、权力架构、战力基线、跨世界机制、玩家已经历的事件。未授权就保留在草案区。

## 交接目标
- 给 `901-world-systems`：哪些地区社会规则可被视为既定约束，哪些只是候选。
- 给 `901-story-factory`：已发生的证据及禁止回溯修改的秘密，不替它写剧情。
- 给未来 `901-character-builder`：人物来源/身份已知与能力适配边界，不分配资源。
- 给上游 `tavern-cards`：经准许发布的内容及条目范围，不代替其打包。
