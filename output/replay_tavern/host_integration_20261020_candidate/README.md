# 901 主持整合测试

本包将 008 主持正文、文风与 136 条世界书接入现有普通检定、战斗引擎和 MVU。用于新建的独立测试聊天，不覆盖正式主持卡、帝都 T0 或已经游玩的分支。

**基线：完整人物卡的 RE 比较配置，不计观澜法。** 帝都 T0 的既有记录明确没有魔力和重筑弃风，本包不能作为 T0 初始存档。六属性及普通技能沿用已确认卡面，战斗资源沿用当前 combat 配置；主角在普通检定和战斗中共用 `actors.player`。健康、满能量仅用于新测试实例，之后进入战斗保留伤势与消耗。

## 安装

1. 将 `public/901-host-integration` 整个目录复制到 SillyTavern 的 `public/` 下。
2. 导入 [主持卡](import/901_主持整合测试.card.json)，打开新聊天。接受内嵌世界书导入、角色局部正则启用、酒馆助手嵌入脚本启用。角色卡包含 MVU 和主持入口两条脚本。
3. 关联世界书应为 `901_主持整合测试_008_20261020`，共 136 条。内嵌与 [独立世界书](import/901_主持整合测试_008_20261020.json) 任选一种，避免同时关联两份。
4. 发送框上方应出现“查看当前状态”“继续战斗／玩家选择”等按钮。控制台应出现 `[901-INTEGRATION] READY`。若当前酒馆没有自动导入脚本，可在该角色的脚本库导入 `901_MVU.script.json` 与 `901_主持整合入口.script.json` 并启用。
5. 保留现有御临风 Persona。包内的 Persona 文件是原 T0 参考备份，不应将其开局装备与完整卡演练合并。模型连接沿用用户现有配置。

运行文件在独立目录中，安装不替换原 `901-rules-runtime`、`901-combat-runtime` 或正式卡。本次请求由角色世界书加载过滤排除其他全局世界书；全局设置不修改。

## 使用与验收

测试场地和对练只属于本包，无正式剧情意义。当前登记两场遭遇：

- `jiang-huang`：姜子尤对黄泉，御临风旁观。NPC 自己选招，攻击和反应由同一程序处理。
- `yulin-jiang`：御临风对姜子尤。进入后等待御临风的本地行动选择；参战声明不等于已执行攻击。

普通发送框可以按顺序测试：

1. 交谈：“我对布莱特说：先看看场地，暂时不要开始演练。”应只有叙述，无战斗与机械扣费。
2. 检定：“我尝试走过旁边的矮横木，保持身体平衡。”测试场景明确为敏捷＋运动、DC 1；失败只落地，没有伤害。程序展示公开骰池依据、保存结果，再交给主持续述。
3. 旁观：“开始姜黄演练，我在场边观看。”分类器选择登记遭遇，NPC 行动到结束，程序写回后续述战后场景。
4. “查看当前状态”，然后刷新并再次查看。伤势、能量和修订应一致。
5. 战后普通对话应承接结果，不能恢复满血、重启战斗或再次计奖。
6. 在**新测试聊天**中发送“我参加与姜子尤的演练”。应停在玩家选择框。“稍后选择”不会扣费，刷新后仍可继续同一回合。

无障碍场地和横木 DC 1 只属于测试场景。用户2026-10-20确认：苍穹弓力量要求4、狮子王及弃风武器体积3、乱红莲自身体积12。流风池上限与启动动作仍保留缺项，使用“主持补参”入口，不自动填测试值。场景不发 XP。未登记的敌人或战斗、仍缺参数的能力会等待裁定，不能据模型叙述自行形成数值。

## 工作方式

普通行动先经主持分类：无需检定则续述，普通检定由程序保存后续述，已登记冲突交给战斗宿主。NPC 的选择输入只包含本轮可见面板、合法选项与相关短能力；历史结算明细通过局部正则过滤。玩家行动与受击反应使用本地选择界面。

规则数值统一存入 `stat_data.901_rules_poc`。进入战斗不重置角色，战后保留伤势、能量和恢复限制；进场请求以玩家楼层、swipe 和操作编号去重。战后叙述失败时结果仍在，“继续战斗／玩家选择”可恢复该次续述。重生成已完成的普通回复复用已保存结果。

“补发已结算报告”只重复展示，不重算。“停止自动推进”在本次进行中的模型行动完成后停止后续推进。当前不支持在同一聊天并行运行其他数值写入器。

发送框上方会保留最近一次处理状态：正在处理、已保存的修订、等待玩家，或请求失败。模型请求失败后，已保存的结算仍可恢复；普通对话失败时重新生成该条回复，战斗中断时点击“继续战斗／玩家选择”。
