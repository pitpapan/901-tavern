采用状态随 005 原条目保留：`CONFIRMED` 才能作为已确认事实；`PROPOSED` 是草案；`SUPERSEDED` 不再用于当前叙述。即使后台事实已确认，也只在角色当期确实知道时成为其行动依据。T0 已有医馆封闭与拘捕是后台世界状态，玩家并未因此自动获知；后期修复的弃风、奖励、神约与未来故事不回填 T0。普通路人和店面细节只是可撤销的本分支演出。

## 隔离配置

1. 将卡导入**新测试聊天**，只让卡内 005 世界书作为该卡的主世界书；不要同时把 004、T0_v1 或 005 放进全局／聊天世界书。正式 GM 卡、Persona、M1 包、旧存档均不修改。
2. 若要尝试规则工具，按 [GM Runtime 安装说明](../../../work/rules_engine/gm_runtime/README.md) 在 SillyTavern `public/901-rules-runtime/work/` 提供浏览器 ESM 文件；本卡角色脚本从 `/901-rules-runtime/work/rules_engine/gm_runtime/native-tool.mjs` 导入 `worldRuleGate()`。角色脚本须在当前卡启用，模型连接须支持原生 function tool。
3. 对话和无需机械结果的观察直接发送自然语言。真正需要数值裁定的行动应由 GM 调用 `trpg901_t0_rule_gate`。返回 `needs_input` 时只报告缺少当期 Builder 定义／当前数值状态，不投骰、不写 MVU、不叙述成败。该门禁并未把御临风转换成可结算人物，也不声称拥有真实授权后的完整运行状态。
4. 正式接入数值前，还须整理并确认 T0 御临风及相关 NPC 的时期专属 Builder 定义、已取得资源、当前伤势／动作／能量和必要装备规格；随后才可复用现有 JS → MVU 单写入、operation ID 与读回路径。不能拿 demo 角色或后期卡面填空。

全局提示词及扩展另有时间、变量和正则控制，测试卡已经要求正文不输出时间／变量检查表或 JSONPatch。本次聊天未出现这些列表，但尚未证明所有全局扩展都与 901 规则写入边界兼容。运行前需在隔离预设中逐项检查有效提示与实际写入来源；此卡本身不修改全局预设。

## 真实试玩记录

本机 SillyTavern 1.19.0、酒馆助手 4.11.2；隔离卡 `901 帝都 T0 隔离运行候选 v0.1`，测试聊天 `901 帝都 T0 隔离运行候选 v0.1 - 2026-10-14@10h01m02s003ms`。玩家均由普通聊天框自由输入：

- 玩家询问布莱特先找医馆还是先安置马匹。布莱特依据失明及交通状况提出先放马，黄泉独立补充；没有替御临风作决定，也没有规则请求。
- 玩家明确同意找马厩并沿街看公开招牌。GM 描述城门、旅店及马厩；玩家可继续调查或另行离开，无固定剧情节点。
- 玩家检查蹄印和车辙，GM 只叙述可见痕迹不足以断言有骑兵通过；没有把推测升为已证事实。这段输出没有规则工具，不能作为一次已结算的检定。
- 玩家随后尝试穿过车流、攀爬湿滑外墙。最初角色脚本等待不需要的 `Mvu` 初始化，门禁未注册；GM 的一次回复为空，两个重生成 swipe 分别直接叙述跌落与成功，均无 JS 结算。这些矛盾成败是失败测试产物，不是分支已结算事实。
- 移除该等待并在隔离卡脚本中保存后，浏览器出现 `[901-WORLD-GATE] registered`。同一攀爬动作的再次生成实际调用了 `trpg901_t0_rule_gate`：`kind=check`，返回 `needs_input`、`computed=false`、`revision=null`，锚定本聊天玩家第 9 楼／swipe 0。GM 最终只说明攀爬需检定及当期数值缺口，没有再叙述攀爬成功、失败或伤害。它同时把上一条未结算的穿越车流叙述成成功；这部分仍不能视为已判定事实。
- 页面刷新并重新打开此聊天后，上述门禁调用和缺项回复仍在。这证明聊天文本及工具记录持久化，**未证明 T0 数值状态或伤势经 MVU 保存**。测试结束后已恢复测试前的 `开拓者-失落之地V1.1-世界书` 全局选择；隔离卡保留其自身 005 主世界书。

## 阻塞与最小后续修正

1. **规则调用尚非硬门禁。** 角色脚本的 `shouldRegister` 回调访问酒馆代理曾抛错，且等待 `Mvu` 导致未注册；两点已从隔离脚本移除。最终复测证明模型能实际调用只读门禁并遵守 `needs_input`，但较早的未结算车流行动仍被后文写成已完成。正式运行需要在发送前对需要数值裁定的玩家行动实行强制门禁，并清理本测试聊天的失败 swipe；单靠提示词与可选 function tool 不足以保证每轮遵守边界。
2. **T0 数值定义不完整。** 御临风现有卡面混有后期成长，当前 HP／伤势、能量、钱药和早期装备规格均有缺口。`worldRuleGate()` 因此固定返回 `needs_input`；不复用 Playable Prototype 的演示人物。应按具体需要确认 T0 Builder 候选及当前分支余额，再接现有内核和 MVU。
3. **全局提示与变量扩展还需隔离。** 原 Playable Prototype 记录过时间／变量列表干扰；本轮正文未复现，但不能把提示约束当作写入保证。验证真实有效提示和 MVU 写入者后，再作正式接入判断。

本轮保留的是可自由对话与探索、且能对一次风险攀爬明确返回缺项的**隔离世界候选**。在前两项解决并完成一次真实 T0 数值行动的 JS → MVU → 续述 → 刷新读回之前，正式 901 跑团的基本条件尚未满足。
