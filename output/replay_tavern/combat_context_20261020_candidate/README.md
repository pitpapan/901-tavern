# 901战斗短指导与历史过滤补丁

2026-10-20。供现有901主持卡手动导入的小补丁：共用战斗短指导，以及过滤历史计算明细的角色正则。能力数值和现有主持规则仍沿用各自正文。

## 手动应用

1. 在正在使用的901主持卡中，将[短指导与结算格式](texts/901_战斗短指导与结算格式.txt)追加到现有主持指令末尾，只放一份。它是[战斗决策初稿](../../../work/replay_research/combat_decision_guidance_draft.md)的运行短版，不与该稿通用正文重复加载。
2. 在酒馆正则扩展中导入[历史结算过滤](import/901_历史结算过滤.regex.json)，选择**当前角色／局部**，允许该角色使用正则。导入一次即可；不要装入全局。
3. 确认脚本启用，作用位置为AI输出，只在发送提示时应用，最小深度为2，最大深度不限制。显示与聊天保存不走此过滤。

本补丁不含整张角色卡，不替换008世界书、实验执行脚本或机器版本入口。已在独立测试卡安装实测，未安装到正式901卡。

## 过滤范围

仅删除发给模型的较早主持回复中、独占行且完整闭合的 `<rules901_detail>…</rules901_detail>` 块。标签是本补丁新增的输出约定，现有engine不会自动生成；只导入正则而不加配套指令，对未标记旧聊天没有压缩作用。

正常“玩家输入后生成”时，最新玩家消息深度为0、上一条主持回复为1。因此保留最近一轮的计算明细，从更早消息开始过滤。继续生成、重生成按酒馆当次组装的消息深度计算；这里的深度是消息条数，不是战斗轮数。

玩家文本、叙事、实际结果、状态账目及世界书不在过滤范围内。未闭合的块保持原文。不会删除通用代码块、JSON、`UpdateVariable`或全部`details`标签；现有901实验接口通过JS写MVU，并不依赖模型输出变量更新块。

示例仅说明格式，不对应任何人物的已结算行动：

```text
斩击命中，对手退到门后。目标本次受到2L，使用者消耗1点能量。
<rules901_detail>
这里放本次公开的骰值与算式。
</rules901_detail>
持续效果还剩2轮；下一步等待玩家选择。
```

较早消息送入模型时仅移除中间计算块，前后的结果、能量、位置和持续时间仍保留；玩家查看聊天时仍能看到计算块。

## 当前状态接口

现有MVU能存取角色状态，但 `readTestSummary()` 只返回生命、动作和最近结果，尚不是完整战斗摘要。当前位置、轮次、冷却与持续效果的统一推进，以及特殊能力执行仍须接入。详见[接口核查与接入范围](../../../work/replay_research/combat_decision_guidance_draft.md#engine与mvu接口核查)。

因此本次不启用旧状态快照过滤。后续每次生成前能从当前楼层及swipe的MVU读回并注入完整摘要后，再过滤被该摘要取代的历史状态。精简当前状态时也不应把完整 `stat_data` 或全部历史操作记录重新塞进提示。

## 检查依据

正则字段和深度语义按本机SillyTavern的[正则执行器](D:/github/sillyTavern/public/scripts/extensions/regex/engine.js)及[消息组装](D:/github/sillyTavern/public/script.js)配置；导入器支持JSON数组。

本地11项检查通过；酒馆独立测试卡已实测两次模型生成，实际发送提示中的旧计算被过滤、最近计算与状态保留，聊天磁盘记录不变。选招和能量扣减正确；动作余额未被完整记录在明细块外，“踏前一步”存在位移歧义，不能把提示指导当作动作合法性的程序保证。

实测还发现全局《开拓者》世界书混入901上下文；临时取消后，酒馆估算的提示总量由189,124降至2,440 token。该减少来自全局书隔离，不是正则压缩收益。测试后已恢复原设置。详见[实测报告与证据](../../../work/replay_research/combat_context_test_20261020/README.md)。
