## 玩家流程

- 在普通输入框写扮演、实际执行的动作、判定和动作／能量消耗。只执行明确声明的部分，保留未用完的动作，等玩家继续。
- 攻击、移动、主动防御和技能判定由玩家声明触发。台词、凝视和站姿不会自行转成技能检定。
- 玩家未声明本次防御方式时，程序返回“待声明”，不计算防御总值。受击声明中的 `defense: normal` 使用基础与被动防御；`defense: block` 使用玩家此前已按规则准备的格挡／守势。没有就绪的格挡不能临时免费开启。是否动用伤害转换另由玩家声明，不代替防御方式。
- 已明确声明的格挡／守势沿用原持续期，在下次本人行动开始时失效，不逐次来袭重复索取同一声明。一次性防御声明只适用于该次受击。
- 对方的动作和应对写成连续场面，不因描写反应而赠送一次攻击。对方离开威胁范围时，御临风是否发动借机攻击也由玩家声明。
- 发送框上方显示单个可展开的玩家状态栏：名字取自当前 MVU 玩家存档，头像取自当前用户设定的已有头像。攻击、防御、生命、能量、速度、剩余动作、状态与属性均由 JS 引擎和 MVU 最新选中存档驱动。未声明防御方式时显示“待声明”；已声明守势沿用原有效期。展开内容在栏内滚动，不覆盖输入框。
- 主持正文只叙事，不附状态 HTML，也不展示其他人的生命、能量、攻防、属性或隐藏增益。直接发送“查看我的状态”只展开状态栏，不进行模型分类、检定或新增主持状态回复；点击状态栏也可展开。
- 没有五个调试按钮、全员状态窗或逐步结算表。旧聊天楼层的自身状态块通过本卡局部正则在显示和模型提示中排除；脚本对已经渲染的旧状态块局部隐藏，恢复旧回复缓存时移除其中状态 HTML。原消息与 MVU 存档不因隐藏而重写。
- 状态栏监听规则保存、MVU 与聊天/用户设定事件；刷新页面或切换聊天后重新读取对应聊天的 MVU 存档，异步旧读取不能覆盖新聊天。尚无本卡规则存档时隐藏栏位，不根据正文猜测数值，也不为显示而生成满状态存档。

规则仍由原战斗引擎和 MVU 保存。声明中的费用不符时，该步不执行；叙述失败可重新生成或发送“继续”，承接已保存结果，不重复投骰或扣费。
