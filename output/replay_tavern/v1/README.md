# 901帝都重玩：酒馆导入包

本包按本机SillyTavern **1.19.0** 适配。F4负责导出与配置说明；用户已进入G并提供首轮实际试跑，本包已据反馈修订，当前修订尚未复跑。御临风继续使用既有人物描述，世界书和NPC片段按首次入帝都的时期筛选。

2026-10-04试跑修订：已更新两位开局同伴的说话方式、狂岚称呼、状态时序、布莱特听觉盲视与自然交棒。已有聊天请按[定点更新说明](../playtest_fix_20261004/README.md)修改相关字段；不需要重新导入整包或重置当前分支。

本版共有120条运行资料：82条世界背景与机制、38份人物片段。其中5条常驻、109条关键词触发、6条默认禁用供手动启用。未载入的完整档案继续保留在作者资料库。

## 导入顺序

1. 在角色管理导入 `import/901_帝都主持.card.json`（历史文件已退役）。打开它，确认导入卡内世界书；若没有弹窗，在角色菜单选择 **More → Import Card Lore**。导入后确认世界书已关联这张主持卡。
2. 在Persona管理使用备份恢复入口，导入 [901_御临风.persona.json](import/901_御临风.persona.json)，选中御临风。若该入口名称在界面翻译中不同，也可新建同名Persona，粘贴 [Persona正文](texts/御临风_Persona.txt)。备份中没有自定义头像，酒馆会使用默认头像；可稍后自行换图。
3. 用主持卡开一个新聊天，将御临风Persona锁定到本聊天。无需创建多人群聊或逐张打开所有NPC卡。
4. 按下表配置世界书；在Summarize中粘贴`texts/摘要提示.txt`（历史文件已退役）。首次聊天可将`texts/开局摘要.txt`（历史文件已退役）放入当前摘要框，后续由真实聊天更新。开局摘要只初始化一次，不能覆盖已经游玩的进度。
5. 接入选定模型后进入G，只做一次开场与短场景体验，并查看实际发送的上下文和摘要接续效果。

主持卡包含世界书全文，但模型只接收常驻与本次触发的条目。**optional目录里的独立世界书与卡内版本内容相同，只在不使用内嵌导入时选用。** 如使用独立版本，在世界书面板导入后关联主持卡即可；不要同时激活两份同内容书，也无需再绑定到Persona或全局。[官方世界书说明](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)

## 世界书起始设置

| 设置 | 本包采用值 |
|---|---|
| 扫描深度 | 4条消息 |
| 最小激活数 | 0 |
| 递归扫描 | 关闭 |
| 区分大小写／整词匹配 | 关闭，适配中文 |
| 计入聊天参与者名称 | 关闭 |
| Context % / 预算上限 | 20% / 5000 tokens，实际取较小值 |
| 预算溢出提示 | 开启 |
| 向量匹配、额外角色字段匹配 | 首版不启用 |

卡内每条已写入扫描深度、100%触发概率、中文匹配与递归保护；全局预算仍须在前端设一次，卡文件不会代替这一步。常驻也占世界书预算；预算满时可能遗漏已触发内容。未选模型前不冒称确定的总上下文或token开销，模型可用窗口与实际输入计数在G检查。

核心背景和两个开局队友常驻。其他具名人物与背景按确认专名触发；触发人物资料不代表人物突然出现在现场。若某NPC在场但多轮只使用代词，可在该场景把对应条目切到常驻，离场后恢复关键词。布莱特、黄泉离队时也如此处理，无需每条回复操作。

“【手动启用】”条目默认禁用，适用于帝等单字名或尚未实名人物。实际确认对应人物进入场景后，启用该条即可常驻；离场后禁用。避免用“帝”“队长”等泛词自动拉入错误人物。

## 摘要设置

在Summarize中选择 **Main API**，使用已选聊天模型；先暂停自动摘要，在场景收束或关键变化后手动执行 **Summarize now**。提示构造选择 **Raw, blocking**，关闭摘要参与世界书扫描，使用普通提示位置。将`texts/摘要提示.txt`（历史文件已退役）填入Prompt；篇幅目标起步600词，中文计数仅作近似，按实际输出调整。[官方摘要说明](https://docs.sillytavern.app/extensions/summarize/)

当前摘要保存的是已经发生的分支状态，世界书保存背景和人物依据。摘要未立即刷新时，近期聊天中的新伤势、承诺和消息仍然有效。需要回到分歧点时使用原生Branch/Checkpoint；没有另外的JSON存档作业。

[字段对照](author/settings_reference.json)只供核对设置位置，**不是可导入的全局预设，不要拿它覆盖settings.json**。本包没有API密钥或后端采样参数；用户已报告使用“gemini flash3.5”，精确API模型ID与渠道尚未核实，完整模型预设另待整理。

## 文件与来源

- import：正常导入所需的主持卡与Persona备份。
- optional：与内嵌内容相同的独立世界书，作为替代入口。
- texts：主持、Persona、摘要提示与开局摘要的可复制文字。
- author：来源映射、暂不加载的条目去向和配置字段说明；不放入模型提示或Data Bank。
- manifest.json：实际数量、输入指纹和检查状态。字符统计不冒充token计数。

完整人物档案、研究证据和后期历史继续在原F1/F2目录。时期未定人物没有因已写成卡稿就进入T0默认包；梦境专属材料与布莱特原线结局也不在运行正文。来源存于作者映射和自定义元数据，人物转述、未知和有效时期仍保留在需要它们的正文里。

## 后续改进

修改稳定设定先回到F1，修改性格与能力先回到F2；只调整T0投影、关键词和当期删节，则编辑work/replay_research/f4_drafts里的两份projection.json。随后在项目根目录运行scripts/export_replay_tavern.py，已有输出时显式加 --replace-generated。生成器只重建派生文件，原始资料和已审正文不受影响；不要直接手改生成卡再期待重导出保留。变更后仅运行一次 node scripts/check_replay_tavern_format.mjs，检查新的导出与本地格式；脚本同时更新压缩包中的检查结果。此检查不连接模型、不写酒馆数据。

已经在酒馆玩过后，先保留当前聊天/检查点再更新世界书；不要用本包开局摘要重置现有进度。Persona重复恢复同一内部key会跳过已有版本，更新时应编辑原Persona正文，避免产生多个同名角色。进入新阶段时以新分支已经发生的事更新当期片段，不能直接启用原线全时期作者档案。
