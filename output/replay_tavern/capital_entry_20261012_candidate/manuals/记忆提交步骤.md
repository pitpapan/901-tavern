# 人工记忆采纳与订正

这一流程适用于你目前已经选用的唯一记忆来源。不另启一套摘要，不重新适配龙血数据库，也不改原团current_state.md。继续游玩前，先在你现用工具里确认记忆来源名称和自动写入开关：已经关闭就保持关闭；如果已开启，但不能可靠保证只写最终保留候选，先暂停自动写入，再使用下述人工采纳。无需上传配置或重新搭建表格。此包没有程序拦截器。

## 场景结束或关键变化时处理

1. 先确定保留哪条回复、哪一个swipe。场景中普通动作连续进行，不逐句停下来审批；明显涉及身份、新旧历史、秘密披露、承诺、重要伤势或消耗时再重点看一眼。
2. 只记录这个分支实际新增的变化。稳定设定继续来自世界书；NPC当下合乎条件的选择与互动可以成为新分支事件，不要求原帖逐字发生过。新编出来的旧背景不因回复被保留就自动成立。
3. 每项少量记录：发生/说了什么，谁说、谁听见或看见，确定性，来源消息及保留候选，上一版记忆编号。传播事件成立与说法为真是两件事；私念可放私有记录，不变成NPC公共知识。
4. 对照事实卡处理冲突：已确认错误订正；有争议的旧背景留为未确认；证言、谣言或猜测保留归属。重要且资料无法回答的设定才向用户提问，不为了流畅补解释。
5. 只把检查后的几项差异手动写入你现用的分支记忆，另记新的修订号。没有变化就不提交，也不让两个摘要源分别写一份。

可直接采用这个简表，每个场景只需几行：

| 字段 | 填写方式 |
|---|---|
| 分支/父记忆版本 | 自己现有分支名与上一次采纳编号；不要填成本包的M1版本 |
| 来源消息/候选 | 哪条保留回复、swipe序号；编辑后重新确认 |
| 变化与主体 | 具体当下事件或具体某人的说法，避免合并成全知结论 |
| 确定性 | confirmed：此项已成立；uncertain：未定；rumor：确实流传的说法；character_belief：某人判断 |
| 归属与知情 | 谁说、谁听见/看见；未知用未记录，不写必定不知道 |
| 依据/授权 | 稳定事实ID或原来源；涉及御临风披露与主动决定时注明玩家授权 |
| 采纳决定 | 采纳、保留待定、排除无据旧事；不同时写进正式事实 |

## 换候选、编辑或分支切换

- 旧候选对应的待采纳差异作废；新候选从未含有的秘密、承诺、伤势和消耗不能继承。
- 如果旧差异已经写进记忆，先保存当前记忆副本，再撤回或订正仅由该候选支持的项目；其他真实发生的事件保留。之后按新保留版本重建差异。
- 同一候选不要重复提交相同变化。父记忆已更新时，把差异重新与当前版本核对，避免重复扣除或重复传播。
- 当前软件若不能可靠关联候选与记忆，这些步骤由人工执行，不声称后台会自动拒绝。无需每次手算hash；作者侧示例保留hash只是为了说明版本关系。

## 已有错误如何处理

以雪老和馆主混同为例，只订正错误身份及随之捏造的医患旧事。旧聊天文本和实际注入摘要若各有一份错误，需要分别处理；仅改世界书不会自动改掉这两个副本。保留无关且有效的会面、行动与后果，不整段重置剧情，不把错误治疗史改挂到馆主名下。

有限代办的合法概述可形成真实传播：前提是玩家已授权告知这些内容，且有实际接收者。NPC问起住处并不自动产生授权；不知道前一条玩家输入时，也不能武断宣布该概述越权。

包中不附带可直接提交的示例记忆；按自己的聊天实录填写上述表格。
