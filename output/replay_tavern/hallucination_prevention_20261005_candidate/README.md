## 直接更新现有酒馆

1. **先导出当前主持卡和关联世界书作为备份。** 本包使用项目内已确认候选；酒馆内额外自定义和分支记忆并未被自动读入。
2. **更新原主持角色。** 打开现有901主持的角色菜单，选择 **Replace/Update → Replace with File**，选[901_帝都主持.card.json](import/901_帝都主持.card.json)。这是更新既有角色的入口，会保留聊天、资源及群组关系，并替换角色资料；普通新角色导入不是这一步。本机自定义角色资料如需保留，使用下方局部更新方式。
3. **确认世界书关联。** 新卡内已经嵌入125条完整世界书。接受导入卡内世界书并关联；若没有自动导入，使用 **Import Card Lore**，或导入[901_帝都重玩_M1_20261005.json](import/901_帝都重玩_M1_20261005.json)后关联该主持卡。两种方式择一，最终只启用这一份内容；解除旧同内容书的重复绑定，不删除备份。若软件给新书名加了后缀，选中这次导入的版本即可。
4. **更新文风模块。** 在Prompt Manager的提示词导入入口导入[文风_prompt.json](import/文风_prompt.json)，更新同ID的901·GM文风模块（901-gm-style-v1），保留一份启用内容并保存当前预设；旧901·GM短示例继续关闭。这是提示模块JSON，不是完整模型参数预设。
5. **留在原聊天继续。** 不导入开局摘要、不重开故事。继续前核对现用唯一记忆工具的自动写入；如果不能区分最终保留候选，先暂停自动写入，按[人工记忆步骤](记忆提交步骤.md)采纳。下一次正常回复后查看实际提示明细一次即可，无需专门复跑。

角色替换入口已按本机SillyTavern 1.19.0前端代码核对，助手没有执行替换或操作酒馆。
