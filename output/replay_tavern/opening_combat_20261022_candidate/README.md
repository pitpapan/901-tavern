# 帝都初始卡正式规则入口

独立卡：`import/901_帝都初始卡.card.json`。独立静态目录：`public/901-opening-combat/`。构建：`node work/rules_engine/gm_runtime/build-integrated.mjs --opening`。不会覆盖旧完整卡、旧baseline、旧实测聊天或旧运行目录。

正式新聊天的scenario与first_mes沿已采用008入都T0开场；136条世界书及UID保留。洞穴实测使用另一个明确标为隔离当前态的聊天，不表示T0已经进入洞穴。四人的初始定义不表示四人同时入队；姜子尤仅为梦境早期定义。

## 正常使用

玩家继续自然语言声明。现有主持分类器登记`capital-stone`（已出现的一具试炼洞穴石像）和`capital-search-party`（已出现的搜查阻拦者）。仅当当前实际场景和明确接战成立时进入。模型从当前聊天提取实际参战者、位置、地图及撤离目标，并给出逐字依据；程序从白名单短卡创建敌人，不接受模型填写属性、HP或装备。搜查模板至多两名老兵与两名城卫，不因上限补满，不因城卫身份自动敌对。

场景绑定先保存到同一MVU根对象的`encounterBindings`，记录`scene-binding/...`操作，再沿原有`enter`进入。刷新恢复同一入场操作时复用已保存绑定；新接战重新提取实际现场。同一实例的敌人使用`instanceId:localId`，保留该人的伤势；换地点或另一批个体使用另一实例ID。相同实例再入场优先沿已保存当前位置，避免退圈后回到最初站位。真实identity未能判断时仍需主持澄清。

已有伤势、能量、箭矢和意志点进入接战时不回满。退出圈/抵达已确认退路属于脱离当前接战，不等于任务完成、通缉解除或其他区域查明。不自动治疗、发XP或奖品。

分钟持续的流风、身法在脱战时保留值和`durationCarry.remainingRounds`；重新进入战斗从该余量承接。**当前没有世界剧情时间时钟；脱战期间实际经过的剧情时间仍须主持计时并更新余量，不能据此无限延续增益。**切回story本身不等于一分钟已经过去。

`combatCarry`同时保存持续效果、冷却余轮、场景实例与已用次数；同一实例再入场保留一次转换等每场次数，新的场景实例只重新建立每场次数，不恢复生命与能量。未到期冷却跨模式按剩余轮数承接，同样需要主持记录脱战剧情时间。

## 主持补参

正常入场不要求玩家手填JSON。确需纠正已确认场景时，主持可用`/901-scene`打开后台登记，或触发本地`901-opening-host-register`事件。后台默认隐藏，没有常驻按钮。登记仅保存当前场景，不自动接战、移动、恢复或授奖。样板须按真实现场修改，不能把它用作剧情发生依据。
