# 一次报信场景怎样推演

以下是F3方法演示，不是原团原文、正在发生的游玩或新开局存档。示例只为解释“资料怎样约束一轮回复”，没有运行模型测试或掷骰，也没有预先确定本次重玩的报信路线。

## 使用的已知条件

示例假设：用户在入城后自行选择报信，现在已经见到原研究所指的守门军官。这个相遇是示例前提，不是主持替御临风选择的开场。

本地资料已确认该军官与达卡斯一方有关。原线中他援引胜利报告，并在特定交涉后下令押人；那些后续动作不自动复现。军官的具体效忠等级、全部内情和是否受控仍未明确。改变表达方式不会让已有关系消失，也不足以证明一切沟通注定失败。[开局研究第8项](../../../../work/replay_research/opening_state_consolidated.jsonl:8)

世界后台的高塔双潮与白魔脱逃已在T0前成立。眼前交谈既不会触发它们，也不会取消它们；军官和御临风是否知道其全部情况，另按消息来源处理。[用户时序澄清](../../../../work/replay_research/user_clarifications.md:243)

## 假设的用户输入

> 我只说明亲眼见到的边关失守情况，请他核实；其他经历先不提。

这一输入授予“报告亲见情况并请求核实”的动作。它没有授予辱骂、透露全部秘密、跟随军官、接受扣押或决定相信对方的动作。如果需要具体证言才能继续裁定，NPC可以在场内提问，不必让主持替御临风编出新的目击经过。

## 这一轮先能确定什么

| 项目 | 本轮处理 |
|---|---|
| 军官收到消息 | 只收到用户实际报告的内容，不附送现代来历、交易细节与完整力量表 |
| 报告的真实性 | 接收到报信不等于已经采信；收到的另一份报告也不是自动正确 |
| 军官的关系 | 保留既有阵营联系；具体阻碍的手段依据当下行动生成 |
| 玩家表现的影响 | 克制表达改变交涉方式，可影响对方选择的手段；不保证关系、利益或结局随之逆转 |
| 本轮可用反应 | 在尚无更多必要条件时，可以先追問来源和身份，保留后续核查、阻挠或处置的空间 |
| 不在场人物 | 没有发出并送达消息之前，不得立即得知这次会面 |

这张表解释裁定依据。正常游玩只呈现场景，不把后台关系表展示给御临风。

## 一种可能的主持回复

> 军官听完，先问起你的来处。
>
> “你是哪支队伍的？把亲眼看见的事说清楚。”
>
> 他没有答应立即派人核实，而是等着你的回答。

这只是依据现有条件可生成的一种分支回应，不声称原帖说过这段话，也没有确认军官内心到底在想什么。它留下明确的交涉点，同时不代替御临风作出回答。

## 如果保留这条回复

当前场景增加三项：御临风提出报信与核实请求；军官收到实际报告内容；军官追问队伍身份和目击内容，尚未承诺核查。只经历一轮短交谈，没有据此虚构准确分钟数、军队出动、第三方获知、任务成功或双方好感变化。

记录示意：`report_received`是已发生；`verify_requested`是请求；`verify_accepted`与`message_dispatched`都没有成立依据。它们是本分支状态描述，不新增世界书条目。

用户下一轮如果选择补充目击信息，军官会得到新增内容；如果选择离开，主持处理他对离开的可观察反应。两种情况均保留其已有关系，不为了复现原线强迫御临风激烈争执或立刻安排右近营救。

## 如果改选或重生成

若这条回复被弃用，军官刚才的具体问题也不进入存档；新回复仍从同一个报信前提出发。若用户把报信行动也改成“先找医馆”，需要回到报信之前的分支点，撤销依赖该次报信的获知与后果；此前已经发生的世界历史保持。

“去找医馆”改变接触路线，不会取消此前已经发生的雪老刺杀及医馆查封。原线较晚才向队伍说明的案情，在世界后台已经成立；推荐信不能直接带来正常接待或安全住宿。现场能发现什么、谁已知道案情、达卡斯是否收到行踪并亲自介入，由本分支实际消息和行动处理，不强制重演原线追捕。具体日时差异见OPENR_009的2026-10-04回查。
