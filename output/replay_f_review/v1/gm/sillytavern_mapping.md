# 直接使用酒馆已有功能

御临风用原生Persona，主持规则放在供模型使用的主持资料中，世界背景由世界书提供，已经发生的故事由聊天与摘要接续。F3要写好这些内容之间的因果和记录约定；原生功能的设置与文件导出在F4处理。

## 现成功能和本项目内容

| 需求 | 酒馆已有承载方式 | 本项目需要准备的内容 |
|---|---|---|
| 用户扮演御临风 | Persona用户角色 | 已有开局Persona；身份及适用的开局描述 |
| 模型扮演主持和NPC | 角色卡的描述、场景等提示内容 | 精简主持规则，配合当前有关的NPC资料 |
| 查询背景和人物 | World Info世界书 | 已编写的世界条目与适用时期的人物片段 |
| 保存已经发生的对话 | 聊天记录 | 只承认当前选择保留的剧情版本 |
| 从过去某处另选道路 | Chat Branch或Checkpoint | 选定分支点及可理解的名称 |
| 压缩长期经历 | Summarize摘要扩展 | 保留哪些事实、人物获知和未决事项的摘要要求 |

Persona本身支持名字、头像、描述及与聊天或角色的绑定，用来明确用户以谁的身份参与。它不是需要本项目再实现的功能。“重要决定由玩家作出”只是一条简短主持约定。[官方Persona文档](https://docs.sillytavern.app/usage/core-concepts/personas/)

角色卡可以向模型提供角色说明与对话场景。本项目把AI一侧写成主持，是内容组织方式；已有NPC档案并不意味着必须同时打开99张独立卡。[官方角色设计文档](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)

World Info将选中的资料加入模型输入。本项目的职责是提供准确且与当前时期有关的条目，让主持据此推演；条目里写着任务条件，不等于已经安装了自动任务结算程序。[官方世界书文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)

## 存档和记忆也优先用原生功能

酒馆的Branch和Checkpoint能够复制聊天到选定消息位置；前者创建后切换过去，后者创建一个具名检查点并保留当前聊天。本项目直接复用这些能力，不要求另建平行的存档引擎。[官方聊天管理文档](https://docs.sillytavern.app/usage/core-concepts/chatfilemanagement/)

Summarize可以生成、保存和使用摘要，当前摘要可编辑，也有恢复上一份摘要的能力。官方文档说明摘要与消息元数据关联；不能把它误说成完全没有回退支持。摘要内容仍可能漏记或误写，本项目补的是摘要应保存的东西，而不是重新开发一个摘要系统。[官方摘要文档](https://docs.sillytavern.app/extensions/summarize/)

因此，首版通常只需自然聊天、在需要时查看一份简短摘要、在重要分歧前创建原生检查点。结构化状态种子用于作者审核和以后可选导出，不要求玩家每轮编辑JSON。自定义外部文件若将来启用，才另行处理与聊天的同步；不把它作为当前游玩的必备负担。
