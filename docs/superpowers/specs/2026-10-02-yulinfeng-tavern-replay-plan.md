**三　完整框架优先的建设范围**

这次先建设整个世界与主要人物的作者资料库，随后整理时间版本，最后制作酒馆导出。工作顺序是：

资料总览 → 全世界主题与人物名录 → 设定和角色参考通读 → 全团记录按场景顺读 → 主题与人物证据整合 → 集中审核 → 正式编写 → 帝都时间版本 → 酒馆适配。

“全面”指覆盖所有现有来源、主要主题和人物，并明确缺口；不要求为每一帖、每一招和每个小动作生成正式条目。全团记录原则上阅读一遍，以场景记录其贡献，之后只回查支持具体结论的原文。资料阅读与反复验证是不同工作，不能为了减少 validation 而跳过必要的阅读。

最终需要形成以下内容成果，而不是只有格式、脚本和验证报告：

| 成果 | 回答的问题 |
|---|---|
| 世界总纲与背景资料 | 这是怎样的世界，它如何形成，又受哪些规则约束？ |
| 地理、文明和社会生活资料 | 不同地区的人如何生活，制度和种族关系怎样影响行动？ |

| 力量与规则资料 | 不同能力从何而来、怎样作用、付出什么代价、何时适用？ |
| 全人物名录与主要人物档案 | 每个人是谁、经历了什么、怎样说话行动、会什么、知道什么？ |

**可扩展性约定**

框架要允许新资料、新剧情和新导出目标加入，也要允许纠错而不重做整个库：

| 约定 | 后续改进如何受益 |
|---|---|
| 实体使用稳定 ID，名字与别名另存 | 改名或确认别名时不重写所有关系；同名、疑似别名先保留待审映射 |
| 原始资料、候选、已审内容、运行导出分层 | 调整压缩方式和酒馆格式不改写正典；重新生成索引不覆盖人工工作 |
| 事实有来源与时间，主观认知有归属 | 可建立其他开局快照，也能区分世界真相、人物理解与后期变化 |
| 人物通用资料和时期变化分开 | 新增某次成长或关系改变时，只补相关变化，不复制整张人物卡 |
| 原线与每个重玩分支分开 | 新选择不会污染原团历史，多个存档可共用稳定背景 |
| 内容格式有版本，导出器单独适配 | 后续换酒馆格式或增加其他前端时，不必重新读原始记录 |
| 引用可反查依赖，来源记录版本或指纹 | 来源修订时，只定位受影响的候选、条目、人物和导出，避免全库重验 |
| 进度和缓存与事实分开 | “读过”“找到候选”“人审通过”不混用；可重建缓存不会变成假正典 |
| 未知与冲突有独立记录 | 新资料能逐项补缺，不需要编解释才能先维持结构完整 |

第一版用普通文件和现有六种条目类型即可。新字段先在工作层试用，确有必要时才升级正式 schema，并明确旧数据的兼容方式；不为将来可能有用而提前建设复杂服务。

为节省工作中的 context，后续默认先读短入口和当前阶段记录，再检索主题/人物/页号，最后按 msg ID 读取全文。索引只保存定位和必要元数据，不把原文再抄一遍；不会以有损摘要代替证据。每次新增或修改资料，只刷新对应索引及受影响的工作项。

**四　怎样让资料易读并且可追溯**

统一约定 UTF-8、稳定文件名和来源编号，但保留原始文件不动。每份来源登记“原路径、资料类别、版本或抓取时间、可用正文路径、所在章节、是否持续编辑、是否有缺图”。同一资料的 HTML、Markdown、JSONL 是不同表示，不应重复计作多份独立证据。

| 文件形式 | 优先读取方式 | 何时回看原文件 |
|---|---|---|
| 已提取 JSONL、TXT、Markdown | 根据来源索引检索，按完整场景读取正文 | 引文、数值、说话者或删节不明确时 |
| 本地论坛 HTML | 重用已有 posts 提取；保留作者、帖子 ID、楼层和引用关系 | 表格、折叠、嵌套引用、图片旁注可能漏读时 |
| PDF | 先提取文本及页码；扫描页才做 OCR | 地图、排版、表格、OCR 不确定内容 |
| DOCX | 提取段落与表格，保留原文定位 | 批注、修订、图片或版式影响含义时 |
| XLSX、CSV | 按表和列名读取，不压成失去字段关系的一段话 | 合并单元格、公式、单位影响解释时 |
| 图片 | 按2026-10-03用户要求只保留已有索引；本次世界观补全不解读图片 | 不从文件名或占位符推断图中信息；未读图不列任务缺口 |
| 音视频或压缩包 | 需要时先转录带时间戳，或登记包内清单 | 声音、图像本身有不可替代信息时 |

没有一种转换可以保证“任意文件都无损可读”。不支持、损坏、加密或缺失的内容记入缺口；会影响主要世界规则、人物背景或起点状态的缺口集中向你提出，次要缺口保留到相关主题处理中。

实际阅读顺序为：场景/人物目录 → 所需页的 preview 或 compact 导航 → 对应完整帖子 → 必要的前后帖 → 对应原 HTML（图片已按用户要求排除）。能力结算必须看全文，compact 会删掉部分规则文字。manifest 中存在旧输出绝对路径和零帖辅助网页，读取器应使用当前正文目录与稳定来源 ID，不能把 manifest 每一行都当剧情页。

建议每次阅读包按一个完整互动或场景组织，初始约 15–40 帖；大战或复杂对话按语义边界拆分，不机械截断。每包只交付候选、证据、矛盾和缺口，不反复生成整章战报。完成后留一段进度说明，记录读到哪里、哪些候选已有人审、下一包依赖什么，换聊天也能接续。

候选的最小记录应包含：

| 字段 | 作用 |
|---|---|
| 稳定 ID、主题与建议类型 | 名称变动后仍能定位；正式世界书仅六类 |
| 候选断言或观察 | 一句话说明原文支持什么，不先撰写正式条目正文 |
| 证据身份 | 设定明述、角色卡明述、主持描述、角色行为、角色言论、用户补充 |
| 确定性 | confirmed、uncertain、rumor、character_belief |
| 来源 | 文件、message ID/页码、楼层或段落，必要时一小段原文 |
| 世界有效时期 | 什么时候已经成立、什么时候发生变化 |
| 揭示与知情 | 哪个角色何时知道、相信、怀疑，或明确不知道 |
| 适用层与分支 | 原团、过渡、续团、特殊插曲；或独立重玩分支 |
| 冲突和处理建议 | 保留双方来源；交由审核，不自动裁决 |

字段是工作层建议，不应直接塞入已有严格 schema。现有正式 schema 不支持的时间与分支信息先放关联表或独立重玩目录，实施时再设计必要的兼容适配。

**五　世界观与背景具体要重建什么**

世界观的成果应当能解释人物所生活的环境、权力和力量的边界，以及历史如何造成今天的局势。不能只有百科名称，也不能为了显得完整而编出设定。

下列主题已在现有设定集中有入口，是研究范围示例，不是本轮新批准的正式条目。涉及后期状态的部分仍需回原团确定时间。[设定集全文](<D:/备份文件/901记录/TRPG outputs/设定 人物/妄想大陆设定集_检索版.md>)

| 内容轴 | 已有材料中的具体主题 | 要整理的关系和问题 |
|---|---|---|
| 世界结构与地域法则 | 四陆一脉、飘零大陆、妄想山脉、大陆间物品与能力的法则限制，L17–18 | 地域之间如何关联；哪种规则有明文，哪些边界尚不清楚 |
| 国家与行政制度 | 帝、八柱将、非世袭考试考核、常务机构与朝堂裁决，L23–26 | 权力怎样运作；官员、军队和监督机构各自能做什么 |
| 民间与秘密组织 | 游击士协会、兄弟会，L30–35 | 宗旨、行动范围、联系方式、与国家及普通人的关系 |
| 域外社会 | 无法地带、狂信者、无法组织、高等评议会，L63–64 | 不同统治秩序、最低规则与普通居民的处境 |
| 种族与文明 | 精灵、矮人与帝国；龙族；娜迦，L24、48、53–54 | 种族特征、历史地位、人口和文化，避免以个体代表全族 |
| 古史与历史遗产 | 永恒之井、古代精灵内乱、精灵王、死亡之翼与黑龙一族的旧战，L53、152、173 | 事件的已知先后、遗产、当代影响；没有记载的年代不编写 |
| 战争与政治背景 | 魔兽长老议会、凌迟统合部族、边境失守、帝都事件及帝国远征，L40–44、182 | 战争的不同阶段、力量组织方式、信息传播与局势变化 |
| 异界与外来知识 | 魔物及魔物之潮、纳萨力克地下大坟墓、白色魔法使与 Phantom，L58–59、125–130、186 | 外来者如何被认识，概念的社会含义如何变化，不自动引入其他作品未采用的设定 |
| 超凡体系与限制 | 假面、腰带、魔宝石与戒指、厌魔石，L161–178 | 获得资格、能力来源、代价、抑制方式、资源管制与规则版本 |
| 技术与普通生活 | 魔法武技改革、卷轴工厂化、人才养成制度，L187；团录中的货币、医疗、交通、委托 | 世界如何实际运行；从具体交易和生活场景归纳，不凭空补经济或人口模型 |

宗教、神祇、灵魂、死亡、复活、诅咒、预言以及特殊梦境也应作为独立研究主题，从人物档案和相关团录中汇集证据。设定集目前没有给出这些问题的完整统一答案，不能把零散表现拼成一套自创宇宙论。

例如，设定集将大陆间法则限制作为世界说明；对“帝曾去尼伯龙根获得永生”的说法则明确标为未证实的传说。腰带过度使用腐蚀心智属于传说，对精灵内乱的影响只是可能。整理后的框架必须保留这些差别，而不是把所有说明写成同样确定的事实。世界简介把某种魔兽扩张解释归于学者，后文又有更直接的设定陈述，也应保留其不同来源身份。

背景需要分成四层：

| 背景层 | 保存内容 |
|---|---|
| 世界与文明的长期历史 | 古史、制度形成、种族经历、技术遗产及长期矛盾 |
| 战役开始前的区域局势 | 边关、帝国、魔兽及其他势力在御临风介入前已成立的条件 |
| 人物自身的前史 | 出身、成长、师承、家庭、旧关系、创伤与能力取得；事实与解释分开 |
| 原团实际经历与变化 | 事件怎样改变局势、关系、性格、能力和知识，逐阶段保留 |

时间至少区分三种：资料何时写下或更新、事实何时已经成立、某个角色何时得知。后期才揭示的古老秘密可以保存在完整作者库；只要原文明确支持它早已存在，就不应因揭示较晚而被抹去，但不能让御临风提前知道。反之，后期新建立的联盟、婚约和新获得的能力不能提前成立。

整理世界模型时，以有证据的关联组织内容：地区承载势力，势力掌握资源和制度，人物在其中有身份与关系，能力受取得方式和限制约束，事件改变其中一部分。关联只是方便理解和检索；“相关”不自动等于“因果”，也不需要为了这张关系表先安装图数据库。

正式世界书仍只用 `world`、`faction`、`location`、`character`、`concept`、`event` 六种类型，一条讲一个核心主题。以上内容轴是资料组织方式，不是新条目类型。人物扮演细节、即时状态、数值规则和导演计划分别保存。每条正式条目至少一处精确来源，复杂条目应能追溯具体断言。

能力要分成三个问题：世界里这种力量如何被描述；这个人在该时点实际掌握什么；本次游戏怎样判定使用结果。人物能力档案记录名称、来源或传承、取得时期、效果、条件、范围、代价、限制、已见应对方式和规则版本。没有写明的距离、冷却、豁免和强度留缺口，不从后来数值倒算初始数值。

需要整理本团的剑术、斗气、魔法、种族天赋、契约、诅咒与特殊装备之间已经展示的相互作用，但不擅自制作统一战力等级。每种力量除规则表之外，还要保留其叙事表现，让 NPC 能自然行动，而不是每次都念技能说明。

游玩裁定规则放在后续适配阶段选择。保留原有明确数值与能力边界；资料不足处提出独立的重玩规则约定，采用后也不改写原团设定。真实随机结果由玩家或实际骰子工具提供，不能将叙事选择伪称为掷骰。

**六　完整人物体系与人物卡**

先建立覆盖全团的角色名录，再决定哪些人物需要完整档案。是否值得完整研究由实际人物内容决定，是否在场只决定运行时加载。不能因为尚未入场，就不整理关键人物；也不能因为角色有名字，就替他补完整人生。

目前的资料至少提供以下研究入口，名单不是完整名录，也不预设所有别名已确认：

| 人物范围 | 已有入口举例 | 研究重点 |
|---|---|---|
| 原参演人物 | 御临风、姜子尤、谏山黄泉、沐透、卡西乌斯·布莱特 | 原背景、个人经历、能力路径、原玩家塑造与队伍关系 |
| 帝国及其关联人物 | 帝、奥修特尔、哈克、久远、雪老、露露缇耶；其他八柱将等从团录补齐 | 公职与私人身份、职责、立场、政治与私人关系的区别 |
| 龙族人物 | 芬尔德／悠悠、谢尔伦，以及原记录中的其他龙王与族长 | 个体经历、部族关系、种族背景、能力及不同历史阶段 |
| 异界与重大冲突人物 | 安兹、白色魔法使、凌迟、古雷姆林等 | 原团采用的身份背景、行为、目标证据、公开面貌和秘密 |
| 地方与关系人物 | 艾利、村医、雅儿，以及前史和各地区有实际作用的人物 | 对世界生活和人物关系的贡献；证据有限时保留短档案 |

[人物原卡目录](<D:/备份文件/901记录/TRPG outputs/设定 人物/人物卡资料集_检索版.md>)直接包含五名原参演人物及安兹、奥修特尔、芬尔德、艾利等资料；[设定集人物部分](<D:/备份文件/901记录/TRPG outputs/设定 人物/妄想大陆设定集_检索版.md:66>)另含帝、雪老、哈克、久远、悠悠、白魔与谢尔伦。其余人物从全文提及与实际场景扩充，不以旧工程曾建成多少张卡作为上限。

每名主要人物应当有“全时期作者档案、历史变化记录、选定时期快照、运行卡”四种视图，共用证据。全时期档案包含背景和原团完整经历；快照不携带后来才取得的能力、关系或知识。人物性格变化需要记录触发事件与变化证据，不能只保留故事结尾的一句话标签。

对于性格，先区分角色卡明确描述、角色自述、他人评价、行为观察和整理者归纳。归纳可以写“在这几类场景中表现出某种倾向”，并附例子和例外；不能无证据补出导致这一倾向的童年创伤或隐藏动机。人物背景能解释什么、哪些地方只存在关联，也需要分清。

语言资料分成两个部分：会哪些语言，是能力与取得时期；怎样说话，是称呼、措辞、节奏、幽默、礼貌与面对不同对象的差别。取少量有代表性的原对白作证据，其他素材留在作者档案，避免把所有语料塞入卡里。

御临风是你的 Persona 和连续性档案。酒馆的 Persona 表示用户所扮演的身份；本项目应把入城时的身份、已建立经历、装备能力和可知信息映射进去。[SillyTavern Persona 文档](https://docs.sillytavern.app/usage/core-concepts/personas/)

御临风的历史性格与语言习惯可供你参考，但不会成为模型替你写台词、主动行动、内心、情绪或新目标的权限。主持可以描述外部结果、已裁定的非自愿生理反应以及你明确声明的动作。沿用[PC 控制边界](<D:/备份文件/901记录/TRPG outputs/docs/pc_control_boundary.md>)。

其余原玩家角色在本次单人重玩中可编为同伴 NPC，证据仍归属于原人物和原玩家贡献。姜子尤、黄泉、沐透、布莱特等都进入完整研究范围；帝都起点只加载实际同行的布莱特与黄泉，不提前把其他角色放入队伍。

每名 NPC 的作者档案与实际加载卡分开。建议提炼以下内容：

| 维度 | 具体做法 |
|---|---|
| 稳定身份与背景 | 已确认的经历、所属、职责、能力来源，以及当前时期是否成立 |
| 性格 | 写“在什么处境下往往怎样做”；保留反例、阶段变化和边界 |
| 价值与底线 | 优先保护什么、何时会妥协；没有证据时不替角色补完整伦理观 |
| 决策方式 | 如何处理危险、权威、债务、陌生人和同伴；单次观察只作条件性线索 |
| 语言 | 同时期的称呼、句式、语气、回避话题；选 2–3 段有出处的短对白 |
| 关系 | A 对 B 的态度与 B 对 A 的态度分开；好感不等于亲密，救命不自动等于效忠 |
| 目标 | 只采用有证据的当前目标，区分公开目标与私人目标；不因剧情需要补动机 |
| 知识 | 知道、相信、怀疑、不知道、隐瞒各自分开，并标获得时期 |
| 能力 | 当前可用能力、资源与限制；详细数值按战斗需要加载 |
| 当前处境 | 在哪里、是否在场、负伤、责任和短期压力；与稳定性格分离 |

证据优先级并非单一排序：角色卡适合身份背景，原场景适合当时行为和对白，设定集适合机构与力量说明。同一句引文被几份战报重复引用，仍是一份证据。多次独立场景中的一致行为可以支持倾向，但不能证明角色“永远如此”。

资料深度按证据和人物作用选择：主要人物完整档案、配角短档案、只被提及者保存身份和有关事实。运行时再按在场情况选择完整片段、压缩片段或不加载；研究深度与加载深度是两回事。NPC 不能为了填满模板被补出爱好、创伤、口头禅或隐藏目的。借用其他作品姓名的角色也以本团资料为准，不自动引入原作百科。

酒馆导出时，身份与扮演约束进入 description，性格压成短摘要，scenario 只保留必要的起点条件，原文短对白进入示例。开场负责展示环境与发言风格，后续动态状态移到场景记录，避免 scenario 永远把人物锁在城门。[SillyTavern 角色设计文档](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)

**七　剧情骨架与固定重大节点**

首先记录原线的事件与因果，再把“如果条件仍成立，会产生哪些压力”变成主持参考。原线结果不是重玩结果，原团后期人物对事件的解释也不自动是真实因果。

| 内容类别 | 默认处理 |
|---|---|
| 开局以前已确认发生的事 | 构成共同历史，按起点有效性采用 |
| 开局时已经存在但尚未揭示的局面 | 主持资料；只有有证据证明当时已经成立才采用 |
| 原线未来事件 | 保留有证据的自主行动及条件；条件仍成立则继续，实际受新选择影响的部分再推演，不照搬玩家参与和结局 |
| 你选定的重大锚点 | 写明固定维度，按锚点合同运行 |
| 普通互动和局部结果 | 由玩家选择、NPC 当时处境与实际判定发展 |

重大锚点应各自有一张短表：

- 来源与原线发生条件。
- 最小固定内容：固定发生、固定时间窗口、固定参与势力，还是固定结果。
- 可变部分：地点、路径、代价、在场人物、揭示方式、成功程度。
- 触发前提与当前状态：未触发、具备条件、已发生、取消或需要裁定。
- 与御临风选择冲突时怎样处理。

优先固定外部局势或危机的到来，少固定具体伤亡、关系归宿和玩家必须做出的选择。若玩家行动已经破坏锚点前提，应显式处理约定冲突；不临时编造一个替身或巧合把剧情拉回原轨。需要改为硬固定结果时，先说明它会限制哪种选择。

帝都的报信受阻、九雪医馆线索、追捕与分线已纳入事件条件档案：守门军官的既有关系保持，是否交涉、取得哪些消息、何时接触右近和实际后果按本次行动判断。御临风必须去某地、相信某人、主动牺牲或接受某关系，都不能由原团记录直接规定。完整分组见[事件档案](<C:/Users/pit/.codex/worktrees/yulinfeng-tavern-plan/TRPG outputs/work/replay_research/event_causality_overview.md>)。

场景骨架采用“入口条件 → 在场人物与所知 → 当前冲突 → 可观察线索 → NPC 有证据的行动空间 → 分支后果 → 退出条件”。少用“第几回合必须发生第几幕”。同一关键线索可以规划多个有来源或获准补充的入口，但不凭空搬运物品、人物与证据。

原团之后在此重玩线出现的变化保存在独立分支，例如 `REPLAY_CAPITAL_01`。不改写 Original Campaign Canon，也不把从早期分歧产生的记录冒充现有定义的 Continuation Canon。新的分支标识放重玩侧文件，不擅自给旧正式 schema 的 canon_layer 增加枚举。

梦境原档保留，默认酒馆导入包、人物卡内嵌世界书、提示词与检索来源均不包含梦境内容；以后明确要求体验时再单独制作。主世界与梦境混合的原帖按段落选取，不整帖打包。只有开局已成立或本分支实际发生的主世界影响进入适用状态；原团后来带回的奖励和知识保留史料，不自动成为本次成长。沐透线、大墓地线是同世界资料，已完成主要归并；制度、势力和人物事实按相关主题及时期使用，完整旁线剧情留档。具体安排见[运行设计第六节](<C:/Users/pit/.codex/worktrees/yulinfeng-tavern-plan/TRPG outputs/docs/superpowers/specs/2026-10-02-tavern-story-runtime-design.md>)。

**八　酒馆中的实际运行结构**

推荐首版使用一张主持卡统筹环境、裁定与 NPC，御临风使用 Persona，NPC 从同一作者档案生成按场景加载的片段。需要单独深入对话的人物再导出独立卡。所有卡共用同一份关系和事实来源，避免一张卡说相识、另一张说陌生。

| 运行组件 | 负责什么 | 加载时机 |
|---|---|---|
| 主持卡 | 控制边界、叙述方式、裁定原则、知识区分、锚点约定 | 常驻，保持短 |
| 御临风 Persona | 当前起点身份与稳定连续性 | 常驻短版，详细能力按需 |
| 核心世界书 | 与每场有关的少量世界常识 | 小部分常驻 |
| 帝都场景世界书 | 地点、机构、当前线索与配角 | 当前地区和场景 |
| NPC 运行片段 | 在场人物的性格、目标、关系与知识 | 只加载在场者 |
| 主持参考 | 当前可能用到的秘密、条件事件与锚点 | 当前阶段最小集合 |
| 当前状态 | 时间、地点、队伍、资源、承诺、待处理行动 | 短而明确 |
| 记忆摘要 | 已发生且会影响后续的本分支经历 | 周期更新，保留聊天回查 |

World Info 可以按关键词动态插入，并能关联角色、Persona 或某个聊天；只有条目正文进入提示词，因此正文必须能独立理解。[SillyTavern World Info 文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)

设计上先按“分支、时间、领域、允许知情范围”筛出可用内容，再在可用内容中做名称匹配或语义召回。未来情节、其他分支和未解锁知识不应进入同一个可任意检索的全文池。

这里的时间与知情字段是项目侧设计，酒馆不会自动理解自定义字段并替我们过滤。第一版通过预先生成帝都阶段包、关闭或不加载未来包、切场景时更新短状态来实现；运行稳定后再考虑少量脚本。关键词触发不是剧情状态机，Sticky/Delay 等按消息计算的设置也不能代替剧情日期或任务完成条件。

NPC 的知情隔离在单一主持模型中主要依靠精简投影和明确归属。只要秘密进入同一次模型请求，就不能声称获得了严格的技术隔离。重要谜底只在当前确有需要时进入主持上下文，未需要的秘密留在作者库；进入后仍需明确哪些人物知道。该方案降低串台风险，不能承诺绝对不泄露。

**每轮怎样推进剧情**

主持每轮承接御临风明确声明的行动，读取本分支当前状态及相关背景，按能力和资源裁定直接后果，再让有关 NPC 依据各自目标、知识和处境作出反应。对已经启动的外部行动，只在世界内时间、消息传播和事件条件支持时推进。回复呈现可观察的新局面，在下一次需要御临风选择时停下；实际保留的结果进入本分支状态。

原团事件要提炼成行动依据、触发条件、阻断因素、知情传播和结果依赖，而不只是章节摘要。你改变报信方式、提前干预或绕开场景，会改变这些条件；模型不能为重演原线强制拘捕、相遇、牺牲或关系。固定节点只约束你事先选定的维度。

酒馆的世界书提供资料，具体判断由模型完成。当前状态的持久保存、场景切换和分支回滚需要明确操作；自定义字段和关键词本身不会自动成为剧情引擎。首版以单主持和场景检查点运行，内容稳定后再加入少量保存/加载辅助，不默认多模型流水线。

完整说明与仅作假设的帝都分支例子见[剧情推进与酒馆运行设计](<C:/Users/pit/.codex/worktrees/yulinfeng-tavern-plan/TRPG outputs/docs/superpowers/specs/2026-10-02-tavern-story-runtime-design.md>)，包括每轮职责、NPC 主动性、离场行动、固定节点、酒馆实际放置与长期状态维护。正式适配交付项由此明确包含主持规则、条件事件资料和分支状态流程。

把“作者拥有多少资料”和“单次请求加载多少资料”分开。首版以实际可用输入额度为准，不依靠模型宣传的最大窗口。

下面是建议的起始预算，不是酒馆默认值，也不是已测试结果。若可用总窗口为 32k tokens：

|---|---:|

| 御临风 Persona 与核心常识 | 1,500 |

| 当前状态与记忆摘要 | 1,500 |

各条目若由世界书加载，其 token 同样计入该层，不能重复计算。中文按目标后端的 tokenizer 或酒馆实际计数测量，字符数不是 token 数。常驻内容膨胀时先检查重复事实和无关角色，而非一味扩大窗口。

建议首轮动态世界书上限约 3k–5k tokens，并与上表一起计总额；扫描最近 2–4 条消息、关闭递归或只允许浅层递归，不启用“为了凑数量而不断回扫历史”的最小激活。中文实体用完整名称、常用简称和确认别名，关闭不适合中文匹配的整词限制。不用“帝国”“力量”“剑”之类泛词广泛触发。预算耗尽会影响激活，递归也可能连带拉入更多条目，需用一个实际场景看提示词结果。[World Info 的预算与激活说明](https://docs.sillytavern.app/usage/core-concepts/worldinfo/#activation-settings)

当前状态建议保留：

- 分支、场景和当前时间；无法确认精确日期时用相对顺序。
- 在场者、位置、伤势和仍生效的外部条件。
- 已知线索及其归属，明确的未知和传闻。
- 关键物品与资源的最后确认值；未知消耗不可变成精确余额。
- 已作承诺、未完成事务、眼前尚未裁定的动作。
- 本分支实际发生的变化及对应聊天消息。

普通场景结束、关键知识/资源变化时更新一次；可把约 10–20 轮作为提醒，而不是每一条回复都发起摘要调用。摘要从自上次快照后的聊天增量生成，旧摘要只是参考，不对摘要反复压缩而丢失出处。重要死亡、关系变化、能力取得与锚点冲突保留原聊天定位和可回滚快照。

自动摘要可能漏掉细节或产生错误，因此它只负责记忆辅助，不自动改写正式正典或稳定人物性格。[SillyTavern Summarize 文档](https://docs.sillytavern.app/extensions/summarize/)

当人物长期离场、地区更换或旧聊天过长时，生成一次“当前状态＋重要历史＋未决线索”的接续包，在新聊天恢复；原聊天归档保留，不全量重新注入。

向量检索作为以后可选项，仅接入已经经过时期与分支筛选的历史片段，用来召回远期回忆。Data Bank 可以存放文本资料，并通过相应检索扩展向提示词提供片段；角色附件也不会自动随角色卡一并导出，因此分发时须另外打包。[SillyTavern Data Bank 文档](https://docs.sillytavern.app/usage/core-concepts/data-bank/)

**十　模型与体验的选择**

把资料提炼、现场扮演、摘要三个任务分开考虑，但第一版不必三个模型同时运行。先选一个你现有、可通过酒馆连接的模型试跑；资料整理可离线完成，不把每次游玩变成多模型流水线。

模型选择看五件事：中文对白自然；同场多人不混淆；能够遵守御临风的控制边界；能维护秘密和不确定性；在合理输入长度下能持续保持因果与人物差异。上下文长只是其中一项。

本轮尚未检查你的酒馆版本、已配置 API、费用偏好和本地硬件，所以不指定某个型号为最佳。接入阶段先使用现有后端做同一小场景；表现不足再换一个候选比较，不开展大规模排行榜测试。API key 在酒馆本地配置即可，不写入世界书、人物卡、规划文件或 Git。

还值得加上的体验组件：

| 组件 | 具体价值 | 初版做到什么程度 |
|---|---|---|
| 关系双向表 | 让 NPC 对御临风的反应有历史依据 | 只记录关键人物的可证实关系与本分支变化 |
| 未决线索表 | 避免谜题和承诺随着聊天变长消失 | 每条有来源、状态、谁知道；不强制自动揭示 |
| 势力行动记录 | 离场势力可以有自己的进展 | 只对有证据的当前行动做更新；新行动作为重玩事件，不回写原团 |
| 场景参与表 | 让未在场者不突然接话或知道秘密 | 维护在场、远程、离场三种状态 |
| 能力与资源短表 | 避免方便剧情而无限施法或凭空拿出物品 | 只显示当前会用到的能力与关键消耗 |
| 开场和叙述约定 | 稳定节奏，给玩家有效选择空间 | 一次推进一个可回应的局面，按需给选项但允许自由输入 |
| 存档与回滚 | 接受重掷、重生或重生成时不留下脏状态 | 状态与实际保留的聊天分支同步，未采用回复不入账 |
| 导出说明 | 防止有卡却缺世界书、图片或附件 | 提供导入顺序、依赖清单和版本说明 |

如果以后要添加“好感值”“命运点”“阵营警觉度”之类机制，先作为游玩设计提出；原资料没有数值时，不把这些指标伪装成原团固有规则。人物心理优先用具体关系与行为描述，避免把一切压成数值。

**十二　限制 validation 的范围**

本项目最需要的是减少错误的事实进入运行包，并尽早看到实际体验。验证服务于这两个目标，不把流程本身变成交付物。

自动检查每个新增包只跑一次，集中报告：

1. 输出能解析、必需字段存在、ID 不冲突，导入格式与实际版本兼容。
2. 新正式内容的来源引用能定位；不会把旧路径、空来源或图片缺失掩盖过去。
3. 世界书类型、确定性、别名规则和 PC 权限没有违反项目约束。
4. 当前包不混入明确晚于开局的装备、关系或知识，也不混入其他分支/梦境领域。
5. 实际提示词大小没有超过约定预算，关键场景内容确实被装入。

结构检查能发现缺字段，却不能证明语义正确。人工重点看世界基本规则、主要势力和人物的整体一致性、时间冲突、入城快照及固定节点；普通条目通过集中候选包审阅，成品只做必要抽样。发现系统性错误再扩大同类检查，不每次都回扫全库。

实际试跑用同一短场景检查六个问题：御临风停顿时模型会不会替他行动；布莱特与黄泉是否能区分；未知秘密是否提前说出；不同选择是否改变局面；现有能力与资源是否约束结果；切场景后能否保留刚发生的关键变化。固定锚点冲突也可放入这次小试跑，不再开一套昂贵测试集。

只修发现的问题，然后复查受影响的片段。没有新的改动或风险，不重复测试。首版不恢复逐帖双人 Pass A/Pass B，不做全库多轮审计，不为文档改字写单元测试，不重验每个旧冻结文件，不自动生成长篇验证报告。

正式资料仍须满足必要人工审核；游玩中的普通状态记录可以批量整理为待审快照，关键变化集中确认。新游玩事件不会自动成为原团正典或永久人物性格。
