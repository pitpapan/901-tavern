# 901 模型调用路径 A/B/C 隔离诊断

此页只记录测试准备。模型请求由用户在 SillyTavern 中手动触发；当前没有执行 A/B/C。

## 已准备的环境

- 使用现有非 Canon 的“901 帝都 T0 重玩基线门禁候选 v0.1”卡，已新建空白隔离聊天；旧聊天未删除。
- 酒馆助手角色脚本总开关与原有 MVU 脚本保持启用；“901 重玩 T0 统一门禁（隔离）”暂时关闭。
- 原有临时诊断脚本已换成指向 [`model-path-diagnostic.example.js`](model-path-diagnostic.example.js) 的加载器，并启用。页面右下角应出现“901 模型调用路径诊断（隔离）”面板。脚本载入时仅显示 `UI / ready`，不会自动请求模型。
- 使用当前 SillyTavern 选定的同一模型和 API 配置。测试脚本不修改端点、模型、温度或 `max_tokens`。

## 用户触发顺序

1. **A 原生聊天**：点击“`A：布防原生聊天`”，然后在新聊天输入一句普通问候并发送。门禁保持关闭。等待正常回复或明确错误；不要点 B/C 与 A 并发。
2. **B 最小 `generateRaw`**：点击“`B：最小 generateRaw`”一次。它只提交 system＋user，要求回复 `OK`。没有玩家聊天消息或结算。
3. **C 实际分类请求**：点击“`C：实际分类请求（不结算）`”一次。它复用当前 [`replayClassificationRequest()`](adjudication-gate.mjs) 和 A 的最后一条玩家消息、A 之前的场景、卡面技能与按行动匹配的世界书条目。优先读取当前隔离 MVU 摘要；若新原生聊天尚未初始化 901 状态，明确标记并使用基线文件中的**隔离测试开场假设**来构造状态摘要。C 仅返回分类状态，不调用结算、MVU 写入或 GM 续述。

B/C 各自最多等待 30 秒，只尝试停止各自的 `generation_id`，不自动重试。A 是原生生成，诊断脚本只观察；若 A 长时间无结果，由用户使用 SillyTavern 原生停止按钮。不要将等待超时解释为已证明的上游故障。

## 安全日志

面板和浏览器本地 `localStorage` 的 `901-model-path-diagnostic-v1` 保存最近 60 条脱敏记录。记录阶段、时间、消息数、UTF-8 字节数、角色序列、可取得的模型标识与主要生成参数、耗时、响应是否为 `OK`／分类状态、可见 HTTP 状态和归一化错误。**不记录消息正文、提示词、世界书内容、凭据或完整模型回复。**“复制脱敏日志”按钮供测试后提交；提供商未返回 `usage` 时不估算 token。

诊断后关闭临时脚本、重新启用 901 门禁，并在新隔离聊天刷新确认。正式 GM 卡、Canon、世界书原始资料及既有游戏存档没有修改。
