# 裁定准确性对照场景 v1

唯一数据集为 [`adjudication-cases.json`](adjudication-cases.json)：12 个假想、非 Canon 场景，比较 A「现有独立分类器」和 B「可能的合并 GM 裁定」。这里只准备输入、预期边界与空白记录格式，没有实现 B、运行模型或生成成绩。

## 将来如何比较

1. 固定数据集、模型版本、采样设置及各自提示版本。每案分别使用 `input` 和 `sharedConstraints`；**不把 `expected` 或评分答案提供给模型**。两种方案提供同样可得事实；若生产输入组装省略某字段，保存实际输入并标明，不能默默为 A 或 B 补上下文。`gmOnly` 可供主持裁定，但绝不能作为玩家知情内容。
2. A 沿用现有分类器；B 待未来另行实现后再测试，仍输出五种既有状态，不为评估新增裁定阶段。当前只填写 `observationTemplate` 的副本，每个案例/方案一行记录；保留原始输出，再检查结构及语义。不需要第二个模型评审，人工对照 `expected` 即可。
3. 分开判定「语义是否合理」「当前契约是否合法」「运行时是否可执行」。多个 acceptable 项是带条件的替代答案，不是看到其中一个标签就自动通过。缺失信息真实存在时允许暂缓；但已明确的事实不得被重复追问。CHECK_REQUIRED 缺少执行必填输入时，记录其识别出了检定需求但不能直接执行，不能补造 DC 使答案通过。
4. 若比较完整一轮，统一从输入提交计时，到可交付叙述或明确失败停止；A 的分类、后续叙述及重试均计入，B 同样计入其实际调用。若只比较裁定阶段，单独标注范围，不能把其成本与完整一轮混比。纯裁定成绩不宣称叙述隐私已通过；只有确实生成的叙述才能评分其泄密。
5. 用 `callRecordTemplate` 逐次记录实际发起的调用，包括超时和重试；`actualModelCallCount` 是这些真实调用的数量。用 provider 返回的 usage 填输入/输出量；缺失保持 null，并设 `usageComplete=false`，不得按文本长度估算。`totalElapsedMs` 使用实测墙钟时间；transportFailures/timeouts 按实际记录填写，未运行均保持 null。记录时删去凭据，不能删掉影响复现的请求条件。

本任务不执行上述未来步骤，不运行 README 中提及的任何模型调用。数据中的 observation/call 模板全是空白，不是基准结果。

## 评分口径

每案记录是否满足条件及最短证据摘录，可同时命中多个错误类别：

| 字段 | 判定依据 |
|---|---|
| missed_required_check | 把有后果的不确定子动作直接当已成功，或绕开必需JS结算 |
| unnecessary_check | 对明确日常行为、合理确定拒绝、资格明确不成立或已定场外结果强行投骰 |
| unjustified_impossibility | 因困难、超常、非语言或信息未知而否认实际具备机制的尝试 |
| incorrect_direct_effect | 奖励没有可信模板、错对象/范围、无保存先叙述生效，或把自动奖励改成主动消费 |
| incorrect_fortune_selection | 把难度/秘密本身当机运理由，忽略最终DP与资格，或不按已授权事件规则处理 |
| hidden_information_error | 透露玩家未知事实、NPC数值、DC、秘密机会存在，或把GM知情当玩家知情 |
| compound_action_error | 用普通片段掩盖危险片段、错误重复结算、擅自增加行动或提前叙述结果 |

汇总时给出可评分案例数和每类命中数，不把传输失败算成裁定错误，也不把失败样本静默删除。另列接口受限与尚未输出可评分答案的案例；不设置未经约定的加权总分。

## 已核对的接口边界

- 以实际 `adjudication-gate.mjs`、`replay-check.mjs` 和最新 `NPC_ORDINARY_CHECKS.md` 为准。旧 `REPLAY_READINESS.md` 的场景奖励弹窗、机运/NPC尚未接入等历史描述已过时；本任务不改这些运行文档。
- 五种状态不变。普通 check 的 PHB 机运是最终DP回退，不是新 verdict。基因锁一/二阶专用D10不能当普通或秘密机运。
- **C10（接入修订后）:** 现有 `CHECK_REQUIRED` 已接受 `{"kind":"scripted_fortune","opportunityId":"可信宿主列出的ID"}`，不增加状态或分类阶段。此路径只允许可信配置明确指定 `phb_fortune` 且规则完整的机会；模型不能提供骰制、概率或可见性。该案现在期望 CHECK_REQUIRED，未授权/缺规则的变体仍暂缓。旧版 UNRESOLVED 接口预期不再用于当前版本评分；比较时记录所用数据集版本/快照。
- **C04:** 唯一直接机械效果使用既有隔离 `demo.scene-cue` 的已定义范围与数值，未制定通用鼓舞奖励。去掉该测试授权后不能执行同样效果。C05/C06 的全军士气效果没有现成模板，不可因同属鼓励而套用。
- C04/C10/C11 是GM行动，现有独立提示主要面向玩家声明。保留原actor、报告输入覆盖差异；不得改写为玩家行动以掩盖能力边界。合并方案也不能因此自动获得额外事实或执行权。
- 多个案例刻意缺少精确卡面/难度输入；可评估是否识别规则边界及真正缺项，不能据此声称测出了数值选取准确率。没有统一固定DC、RP加值或奖励答案。

## 离线与在线的界线

离线可校验JSON结构、12案覆盖、状态集合、必填事实/边界字段以及空白结果是否未被伪填；还可人工核对契约支持范围。离线不能证明任何模型的裁定准确率、调用数、用量、延迟、稳定性或实际叙述保密性。这些必须等实际模型响应与provider记录。

本次只新增数据集和本说明；不修改GM Runtime、NPC检定、MVU、卡片、世界书、Canon或存档，也不新增评测框架。
