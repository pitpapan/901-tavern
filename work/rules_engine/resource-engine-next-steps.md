# 901 通用规则执行器下一批实施计划

> 执行方式：当前会话逐任务实施，使用 `superpowers:executing-plans` 的逐项验证方式；不另建工作区，不自动提交、推送、部署或开启外部模型测试。用户已授权继续，无需再审批本计划。

**目标：**补齐来源伤势、待续事务、编译类型和旧角色贡献迁移，使新增已有机制的资源只需要正文、契约与行为样例。

**架构：**复用现有浏览器ESM、Python编译与MVU写入边界。先给现有消费者补接口和可追踪来源，再逐条替换旧分支；不先搭空框架。真实未决策略隔离在契约中，其余任务继续。Q1–Q5现已获采用，实际落地范围见主设计§24。

**技术栈：**Node本地测试（`--test-isolation=none`）、浏览器原生ESM、Python标准库、既有MVU。

**设计依据：**[resource-engine-design.md](resource-engine-design.md) §3–13、§20–23；本文件中的新接口均为待实现，不能作为现行运行API。

**当前证据：**2026-10-25完整JS580/580，契约270、动作106、基础程序78、合法无基础程序130、fullyVerified=0。此为上一实施批次结果；本规划不新跑行为测试，不改变已安装版。

## 全局约束

- 不读取 `work/replay_research/special_dream_01_gm_draft.md`。
- 不用后期NPC模板覆盖T0，不凭模板补能力、属性、XP、池余额、库存、装填、冷却或已用额度。
- 观澜：六属性及白刃/运动/学识主子技能逐级减1、最低1；完整D技艺一次减1；专长、体质、进化及其他资源不减。悟法XP仅本树完整D技艺一次付清，不混付、不分期。
- 脆弱/报偿跨施法者独立；同施法者重施不清本轮用量。加速术由受术者选择新旧、正常扣费、额度不重置。
- 本次允许治疗A时A优先L，不扩展治疗资格；这个采用不是受伤升级时的来源顺序。
- 不删除历史断言、不以缺少程序冒充缺参数；新设计未实现与实际规则未决分别列出。

## 任务1：来源伤势服务与唯一写入口

**文件：**新增 `work/rules_engine/resource-wounds.mjs` / `.test.mjs`；修改 `core.mjs`、`healing.mjs`、`combat/engine.mjs`、`combat/mechanics.mjs`、`gm_runtime/rule-actions.mjs`、`gm_runtime/resource-program.mjs`、`mvu_poc/adapter.mjs`；扩展现有 `resource-derived.test.mjs`、`recovery.test.mjs`、`mvu_poc/adapter.test.mjs`。此模块不得导入core或解释器，避免新增环。

**权威存储：**拟用 `state.woundLedger={version:1,batches:[...]}`，记录实际受损份额，完好格仍由health表示。每批有稳定 `id`、`severity:B/L/A`、正整数 `count`、`origin`、`restrictions`；限制用结构化规则来源及 `recovery: aggravated/naturalOnly` 表达，不写法术名称分支。历史无来源的批标为 `legacy-unattributed`，这是迁移标记，不是假造受伤事件。拆分份额保留父批ID及真实变更事件ID；同限制但不同来源不能仅为省条目而吞掉来源。

**接口：**

- `decodeWoundLedger(actor) -> {status:'ready', ledger, migration}|{status:'needs_input', reason, evidence}`：只读，读取新账本或真实旧 `recoveryLocks`，校验按伤型计数；双份旧carry不相等时不选一个覆盖。
- `transitionWoundLedger(ledger, changes, {eventId, choices, policy}) -> {status:'resolved', ledger, changes}|{status:'needs_choice', candidates, cursor}`：原计划接口；现行transitionWoundShare已按用户采用的普通优先、特殊逐格随机实施，来源升级不再返回needs_choice，详见设计§28。
- `assertWoundLedger(health, ledger)`：每伤型批次数与health一致，任何限制份额不超过实际伤数；不修写数据。

**实施顺序：**

- [ ] 先在现有伤害＋治疗集成用例中复现：无完好格、1份受限L及其他A，新增L将唯一L升为A，但原锁仍停在L。断言真实升级结果与锁，而非只测新辅助函数。
- [ ] 实现只读旧数据解码：无锁、唯一锁、部分锁、同来源carry副本都能保留已有事实；锁数超过实际伤型时报告明确迁移缺口。
- [ ] 在core伤势转换处使用同一份额转换结果，同步health与账本。`applyWounds`和`advanceDeterioration`不能一个更新账本、另一个只改总数；容量下降沿已采用D11重放，不用旧限制凭空造伤。
- [ ] 将两处治疗、伤害和场外恢复收敛到该写入口；旧actor锁只作一次迁移输入，迁移后从新账本投影兼容展示，不能保留另一可写副本。
- [ ] 新伤附加限制也通过该服务：已有伤被升级时保留原限制；若新旧限制组合会影响结果且无条文，不擅自覆盖或放宽，记录待定组合。它不阻止唯一旧限制迁移。
- [ ] 场外/战斗/MVU出入保存账本，缺来源记录不从角色后期卡补齐。用JSON往返、连续升级及治疗消耗证明份额/限制守恒。

**验收命令：**`node --test --test-isolation=none work/rules_engine/resource-wounds.test.mjs work/rules_engine/resource-derived.test.mjs work/rules_engine/healing.test.mjs work/rules_engine/recovery.test.mjs work/rules_engine/mvu_poc/adapter.test.mjs`。

**依赖边界：**Q1已采用普通优先；普通耗尽后多种不同受限恢复来源的选择仍需完整待续事务，当前不自动选。每日额度已获采用。生命分流不能在此任务一完成就标记整术完成。

## 任务2：先有结果、后有选择的持久化续算

**文件：**新增 `work/rules_engine/resource-continuations.mjs` / `.test.mjs`；修改 `mvu_poc/adapter.mjs`、`combat/transitions.mjs`、`combat/runtime.mjs`、`gm_runtime/resource-program.mjs`、`gm_runtime/rule-actions.mjs`、`gm_runtime/replay-check.mjs`；扩展对应已有测试。

**范围更新（2026-10-25）：**用户已将伤势来源取舍改为默认随机，该分支移出待续事务需求；下述为其他真正投骰后选择保留的设计，不为伤势升级另造等待窗口。

**问题证据：**现有 `combat/transitions.resolveStep` 的pending保存的是投骰前反应声明，恢复时调用act；它不能直接承载已经投骰、已支付后的来源选择。不能把投骰后的NEEDS_INPUT直接抛到事务外后重新执行原命令。

**接口：**`suspendProgram(frame, choiceRequest) -> PendingRule`；`resumeProgram(pending, choice, context) -> RuleOutcome`；两者返回数据、不自行写MVU。

`PendingRule`至少保存 `schemaVersion, id, parentOperationId, ruleBinding, actorId, cursor, locals, payments, rolls, emittedEvents, awaiting, choiceRequest`。`ruleBinding`含能力ABI、资源版本、规范化程序摘要；`cursor`为稳定stepId＋目标位置。`rolls`按消费者ID记录真实骰数组/结果，不能只存最终成功数而丢失爆骰证据。状态变更与待续帧在同一MVU提交里保存。

- [ ] 后续具体资源若产生真实投骰后玩家选择，补该资源的续算用例；伤势默认随机已用实际MVU事务验证保存后不重抽，不再拿它充当待续选择场景。
- [ ] `operations[parentOperationId]`保留原输入签名及awaiting/final状态；每次选择有自己的operationId并引用parent，不能复用同ID改请求签名。重复原命令返回当前收据；重复选择返回相同结果。
- [ ] 续算读取当前MVU revision，核对awaiting人物、真实候选及所属事务；不使用最初旧revision强行覆写。待选择期间按现有战斗窗口限制可发生的动作，反射引起状态变化后重核仍未结算的资格，不重算已发生阶段。
- [ ] 候选代码/契约版本变化时，未完成帧必须匹配原ABI和程序摘要；没有匹配实现或显式迁移就返回RULE_VERSION_MISMATCH，不自动用新版重新掷骰。先不建设远程历史代码服务。
- [ ] 分类器只看到所需选择、合法对象及可公开结果，不看到他人隐藏状态；它提交选择ID，不能提交cursor、原骰值、价格或修复补丁。

**验收命令：**`node --test --test-isolation=none work/rules_engine/resource-continuations.test.mjs work/rules_engine/mvu_poc/adapter.test.mjs work/rules_engine/combat/arena.test.mjs work/rules_engine/combat/declarative-actions.test.mjs`。反应窗口现有用例位于arena/declarative-actions，不新增同义重复套件。
