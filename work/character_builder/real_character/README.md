## 缺失、冲突与引擎边界

- **卡面覆盖差异：**按现行 RE 基底，体积 12 的调整为＋3，力量 8 得基础生命 `2×8＋2＋3＝21`；原卡明列 20。候选保留 20 的 `final` 覆盖；未推定少 1 的原因。
- **攻击自动成功待核：**卡面写 2，内核以已列属性和肉搏主／子技能默认门槛得到 1。原卡未解释另一个自动成功的来源；不以运行默认值覆盖卡面，也不声称该攻击可结算。
- **原卡未列：**意志当前值、伤势槽、当前动作、先攻、视觉、反射、强韧和具体召唤后的时间／资源状态。`demoInitial` 中健康、意志满值 5、动作 ready 均是隔离演示假设；内核算出的其余衍生值不是已确认卡面值。
- **未支持：**灵体与特殊伤害类型、飞行、召唤／召回、灵力侵蚀计时、灵力疲劳、死后休眠、咆哮波范围／反射豁免、死硬和灵异第六感。这些保留在 `abilities` 与 Builder `report.unsupported`，不能用于相应结算。
- **资源三项独立核对：**原文确认乱红莲由狮子王召唤，未确认乱红莲持有狮子王；现有四项 PHB／RE 目录样本没有狮子王或其天生武器；没有针对这两项的独立 901 采用记录。因此 production Resource Adapter 的 ID 选择为空，Builder 不获得任何资源数值效果。原文存在、人物关联、901 采用和引擎支持没有合并成同一状态。

## 运行与 MVU 形状

在仓库根目录运行：

```sh
node work/character_builder/real_character/demo.mjs
node --test work/character_builder/real_character.test.mjs
```

Demo 用 Builder 构筑临时健康状态，再用 `core.mjs` 对感知 4＋求生 3 作 DC 1 的确定骰序普通检定；该操作不依赖任何未适配能力。测试将结果放入现有 `stat_data.901_rules_poc` 的 `actors[id].state` 形状，并以现有 MVU 适配器的只读调试接口读取。没有浏览器运行或 MVU 写入。

Story Factory 接口目前只适合传入有完整来源的**候选定义**并显式给出缺项／未支持报告；它不能凭叙事档自动生成可信 NPC 数值。正式自动构筑前仍需要按时期的权威数值卡、独立资源采用及人物取得记录，以及特殊效果按需适配。
