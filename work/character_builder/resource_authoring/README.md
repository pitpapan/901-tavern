# 资源撰写入口

本目录保留资源底库修复时整理的规则卡、特性和样板，供已授权的资源创作检索参考。后续撰写流程、修订要求和资源成稿在独立的 `901-resource-authoring-kit` 仓库维护，本目录不会自动同步。这组文件不新增规则权威、审批程序或引擎接口。RE 旧称“称号／训练”统一写为**能力组**；主／子技能与可购买资源“技艺”分开表述。

## 每批读取顺序

1. 用几句话明确用途、对象、实际新增玩法、资源阶位和世界强度上限；D/C 等预算标签不能直接等同 T1/T2/T3。先确定核心打法或解决的问题，再分配预算。
2. 读 [常用规则卡](common_rules.md) 的相关行；普通低中阶资源首次可读完整短表，同批不重复读。有具体冲突才沿链接回查融合正文。
3. 在 [特性速查](traits.md) 找相关预算与条件，并选 [定标样板](samples.md) 中 2—3 张相近卡；用下方 `cards` 命令按 ID 取卡，避免整页读入所有样板。未覆盖的机制再搜完整底库，读取命中段落；不要每次通读全部样板、原书、世界设定或外部资源作者指南。
4. 输出资源正文与紧邻的简短预算／价格依据；保留动作、触发、目标、持续、叠加等适用条件。确为类比估价就写明，不能把凑出的预算冒充原文明价。
5. 一次检查：预算合计、升级是增量还是替换、动作与反应锁、同类加值、旧价换 XP 的身份、普通操作资格、来源状态。只有具体错误或尚未解决的机制才补查。

**设计建议**：能力组的特性最好共同支持一种可辨认的行为；进阶说明增加了什么选择，或为何只增加数值已足够。强效果可以有明确成本与限制，不必一律压成微小 DP。以上是设计建议，不是新的强制预算规则。

## 定点检索

完整底库：[入口](../../../901_rules_source_library/README.md)；[按问题索引](../../../901_rules_source_library/indices/mechanisms.md)。下例从 `TRPG outputs` 目录执行，命令只读取本地数据：

```powershell
python -X utf8 901_rules_source_library/tools/library.py cards CR-04 TB-01 T-02 S-01 S-08
python -X utf8 901_rules_source_library/tools/library.py search 剑盾战斗 --kind rules --limit 3
python -X utf8 901_rules_source_library/tools/library.py search --kind resources --tag 协作 --limit 5
python -X utf8 901_rules_source_library/tools/library.py read 'content/RE/01_rules/01_建卡与属性/战斗专长.md' --start 200 --lines 35
```

搜索结果提供原文路径及行号，默认排除待重置、已移除、施工条目；明确研究旧例时用 `--include-legacy`。机器片段和关键词标签只帮助定位，不能证明语义匹配、价格、完整条件或 901 采用状态；查看前后段落，防止截断条件。普通主／子技能请查规则索引；搜索别名“技能→技艺”只帮助寻找资源。

## 模型与验证

常规写作可用 **Sol High**，资料维护用 **Sol Medium**；这是本项目的工作安排，不是质量保证。特殊机制无直接标尺时明确具体缺口，沿现有规则处理。没有必要为每份草稿安排一次 Astra 重写。

一次读取准备材料的成本应按同批资源摊销。记录实际读取字符数、检索次数、修改次数与具体规则错误；没有模型计费日志时不把字符数说成 token，也不编造节省比例。规则稳定性与用户对创意的评价分别记录。
