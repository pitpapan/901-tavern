本包从 GM“剑”的原帖提炼叙事方式，用于首次进入帝都的重玩。它包含两条可单独启停的提示和一段修订开场，供你审阅后手动使用。2026年10月4日已根据用户首轮试跑修订；修订后尚未复跑，酒馆由用户手动更新。

主文风提示为 **1,187 字符**，可选短示例为 **446 字符**，合计 **1,633 字符**；这是文本字符数，不是模型 token 数。修订开场为 195 字符，替换原开场后作为聊天消息保留。49 万字符的研究语料不会加载进酒馆。

这是可并入你自己预设的**提示词模块包**，并不是已经配好模型、采样参数和连接的完整预设。这样可以保留你随后选择的模型设置，也便于单独修订文风。既有主持卡继续负责 F3 的推演规则，世界书与人物片段继续负责资料；本包没有重新复制这些内容。

## 手动加入你的专用预设

以下对应本地 SillyTavern 1.19.0 的 Chat Completion。界面翻译可能不同，括号中保留英文入口名。

1. 在 **AI Response Configuration** 的预设区域，把准备使用的当前设置另存为“901 GM叙事”。这个名称与主持卡名不同，可以避免同名预设的自动关联行为。模型和参数仍由你选择。
2. 找到下方 **Prompt Manager / 提示词管理器**，使用它底部的 **Import a prompt list / 导入提示词列表**，选择本包的 `901_GM文风.prompts.json`。**不要用顶部完整预设的导入按钮。**
3. 在提示词管理器底部下拉中选择 **901·GM文风**，点击链条图标 **Insert prompt / 插入提示词**。新插入条目初始为禁用，需要点亮启用。
4. 把这条拖到 **Main Prompt 后面**。若使用可选示例，同样插入、启用 **901·GM短示例（可选）**，紧接文风条目。保留其余世界书、角色描述、Persona、聊天等标记的原有相对顺序。
5. 保存这个专用预设。首次体验建议两条都启用；以后若模型已能保持节奏，可关掉短示例，只保留 1,187 字符的主提示。

文件只合并两个独立 identifier，不替换 Main Prompt，不写模型、采样参数或连接。空的 prompt_order 保留现有顺序，也意味着**导入完成不等于已经插入并启用**。再次导入同版会替换这两个同 ID 条目的正文；你若已手动修改，先保留自己的版本。

若找不到提示词列表导入入口，也可以手动新建两条提示，粘贴对应 txt：Role 设为 System，Position 设为 Relative，Triggers 只选 Normal、Continue、Swipe、Regenerate。保存提示后仍需插入、启用，并保存整个预设。[官方提示词管理说明](https://docs.sillytavern.app/usage/prompts/prompt-manager/)

## 对白与内心约定

“……”是说出口的话；玩家写的【……】是御临风未说出口的内心。NPC不会仅因这段文字出现在聊天中便获知其内容，想法也不自动算作已经执行的动作。主持不替御临风补写内心；NPC的心理通过对白与可见言行表现，不单独输出内心独白。

此约定已写入主文风模块与F3主持规则源稿。已经导入模块时，可重新导入本包以更新同ID正文，再保存你的专用预设；如果改过该模块，也可只把这条约定手动补入。无需重导旧F4世界书或人物卡。

## 帝国环境的表现方向

主模块已加入用户确认的西方魔幻／日式JRPG风貌，并保留原文中的城门、城堡与整齐规划的城市轮廓。既有圣庙、宫殿梁柱和防御符文照资料保留；不会因人物参考《传颂之物》就把整座帝都改写为东方古城。具体地理、建筑样式与制度不由这种风格标签自动补齐。

## 替换开场

打开现有的“901·飘零大陆主持”卡，把 **First Message / 第一条消息** 替换为[修订开场](texts/901_帝都开场_修订.txt)，保存角色卡。世界书、Persona、Scenario 和主持规则沿用现有版本。

修改卡片不会自动重写已有聊天的第一条消息。如果聊天还停在未游玩的开局，可以编辑那条现有开场；如果已经开始游玩，保留进度，只让文风模块影响之后的回复。想从新开场开始时再另开一条聊天即可，不需要同时维护两个故事会话。

这段开场以用户挑选的 P1 #78 抵都两段为底稿。保留赶路、露营与投宿、翻越山丘、初见城门城堡和与现代及沿途村镇的对照；修正病句和“失明的布莱特也看见”的措辞问题。没有补造城门盘查、守卫对白或新地理。原文中御临风与黄泉的惊叹属于这个指定历史开场，此后的御临风新反应仍由玩家决定。

本包没有把短示例塞入角色卡的 mes_example，而是让它与文风模块具有相同的生成类型限制。F4主持卡的 First Message 仍保留旧开场；不用重新导入整张卡或世界书，按上述方法替换 First Message 即可。

## 正常叙事与后台任务

两条提示只配置 Normal、Continue、Swipe、Regenerate。通过原生 Prompt Manager 组装的 Quiet 与 Impersonate 请求不会加入它们。模块本身也说明：明确要求摘要、填表、资料问答或规则解释时，按该任务格式回答。

这不是对所有插件的全局拦截。当前检查到的龙血玄黄 Chat Completion 填表通道使用自己构造的 messages，通常不会自动继承这里的文风提示；隔离来自它的请求方式。不要把文风提示、示例或原始语料再粘到数据库填表模板、全局世界书或 Data Bank。本包也没有完成尚待处理的龙血玄黄表结构适配。

## 后续如何改进

源稿在 [authoring.json](../../../work/replay_research/gm_style/v1/authoring.json)。要整体更新，修改其中的模块或开场，再运行 `python -X utf8 scripts/export_gm_style_pack.py --replace-generated`；这只重建本包拥有的派生文件，不修改安装中的酒馆、世界书、人物卡或原团记录。

无需为文风先做一轮大规模验证。模型确定后用一个实际想玩的场景体验即可：关注它是否接住行动、NPC 是否在具体情境中说话、长短是否合适。如果出现问题，带回那一小段输入与回复，定点调整相应规则或替换一个例子。保存后的预设可继续复用，不需要重做整份资料工程。
