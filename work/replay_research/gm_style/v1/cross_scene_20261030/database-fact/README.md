# 正式数据库纪要进入续写的隔离实测

2026-10-31，Terra 6.1 High 在本机酒馆操作独立角色「901 正式数据库事实验收 20261031」。新角色沿用正式主持入口的完整代码、现用模型和数据库模板，主世界书换成专用副本，再绑定同样的其余五书。主入口字节哈希及绑定见 [installation.json](installation.json)。本批使用人工构造的一行公开测试事实，只适用于这个隔离分支。

正式角色的数据库写入目标配置为 `character`，即当前角色绑定的主世界书。欢迎页的另一目标属于欢迎页配置。正式原聊天的既有检查点仍为九张空表。为区分从数据库读取和从聊天猜出，测试只把「青鹭七扣」放进独立聊天的数据库检查点「纪要表」DB901-01 一行，明确三个人都听过。种子聊天三条，正文、问题、角色卡和复制时的主书都没有这个记号，聊天也没有原生 Summary。

| 实际环节 | 观察 |
| --- | --- |
| 数据库 → 主书 | 未手工生成世界书条目。打开独立角色后，数据库界面读到 DB901-01，插件在专用主书生成 UID 1 的常驻纪要，深度 999；所有现存世界书中仅该副本含测试记号。原主书 64 项仍受保护。插件重存副本时也重新序列化了这 64 项的部分字段，不能将副本概括为只追加了六项的字节拷贝。 |
| 主书 → 请求 | 世界书激活记录含该 UID。分类请求含整行一次，实际续写的系统消息中也仅出现一次，在 `<记忆回溯>` 内。另有被主持入口拦下的原生外层组装记录。 |
| 请求 → 剧情 | 玩家只问摊主当众说过的碰头记号。黄泉答“青鹭七扣。”，符合在场者知情边界。发送一次，没有重抽。 |
| 存档 | 隔离聊天 3 条增至 5 条。普通对白走 NO_CHECK，前后 revision 均为 0、操作集为空。277 份测试前的既有文件及现用模型、记忆配置核对通过。 |

本次验证的是已有纪要进入正式入口的一次普通对白续写。当前配置的自动填表关闭，这批没有测试从长对话自动提取事实、战斗叙述的另一条请求路径或多聊天共用同一主书时的隔离。测试纪要只留在新副本。请求摘要、实际回复和状态见 [result.json](result.json)。原始采集保存在隔离聊天自身的元数据中。
