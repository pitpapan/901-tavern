## 发现、根因与隔离修复

**人工摘要漏载。**基线第9轮回答正确，但其真实续写请求中摘要为0份，只有被门控停止的原生外层请求包含1份。实际入口 `modelOptions().ordered_prompts`显式列出历史、世界书和文风，却缺少既有六书生成入口中的 `retainedBranchMemory` 导入与读取段。完整历史仍在，因此单凭答对不能证明摘要链有效。

[candidate-entry.js](candidate-entry.js)只补回已有 `branch-memory.mjs` 的导入及 `chat_history` 后的同一读取段。模块沿原生Summary的前一楼约定读取当前保留分支的 `extra.memory`，不读取弃用swipe，不生成摘要、不更新记忆。现有3项针对回归通过。此候选只用于本批明确选择原生Summary的隔离场景，不能据此替其他记忆工具切换来源；正式汇合时须保持实际使用的唯一记忆来源约定。

**未声明动作。**基线第2轮输入只询问两名同伴是否愿意同行，回复却写“顺着御临风示意的方向”，补出了未声明的手势。实际请求已含完整文风和历史，末尾指令列明不补台词、心理、选择、承诺，却未明确动作。候选只将这一句改为“不补御临风未声明的动作、台词、心理、选择或承诺。”，不增加动作词黑名单，不改变已授权动作的客观承接。前后文字见[candidate-change.json](candidate-change.json)。

基线仍有擦桌、湿街等重复环境描写；它们属于本样本观察，不能把旧修复通过夸大为所有文学问题已经消除。本批不因每个修辞偏好再开一轮改写。

## 夹具失败保留

候选第一次09请求被readiness阻止，真实分类0次、续写0次。父代理最初只复制了裸 `stat_data`，遗漏完整MVU初始化载荷与 `initialized_lorebooks`，打开卡后初始化覆盖了该根；这不是叙事模型失败，也不是摘要读取失败。未改正式readiness保护。

完整失败JSONL已仅本地备份，失败采集保存在[candidate/attempt-1-readiness.json](candidate/attempt-1-readiness.json)。修复先将UI导航到about:blank停止活动，再恢复同一隔离聊天前八轮，复制来源第16楼完整MVU载荷，仅将901规则根chatId重绑定；revision0、operations为空。详见[种子来源](candidate/seed-provenance.json)与[夹具修复](candidate/seed-repair.json)。正式原聊天、基线聊天及源根均未写入。修复后才重试09，不把0模型调用的夹具失败算作文学重抽。
