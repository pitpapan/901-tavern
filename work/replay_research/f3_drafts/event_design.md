# F3 事件推进设计稿

状态：provisional_requires_human_review。供主持规则与状态方案整合使用，不是已开始的游玩、正式世界书、酒馆配置或软件。配套 `event_seeds.json` 是最多六条的作者事件库样板，不是每轮整份发送给主持模型的材料。

本稿直接复用酒馆现有聊天、分支／检查点以及摘要和提示位置；它规定主持如何推进、摘要该保留什么，不要求另造角色设置、状态机或后台进程。事件 JSON 只供作者检索与后续选取，正常游玩无需每轮手工跑表。

本稿沿用已经确认的运行设计：从三人将入帝都、尚未执行原线 #81 行动的 T0 开始。保留此前历史与已证关系，允许新选择自然改变后续；御临风的行动与成长由用户决定。梦境默认排除，主神与幻剑旧机制在 T0 已移除。设计依据见 [runtime design](<../../../sources/legacy_evidence/docs/superpowers/specs/2026-10-02-tavern-story-runtime-design.md>)、[OPENR 开局整合](<C:/Users/pit/.codex/worktrees/yulinfeng-tavern-plan/TRPG outputs/work/replay_research/opening_state_consolidated.md:7>)、[UCL_20261003_007](<C:/Users/pit/.codex/worktrees/yulinfeng-tavern-plan/TRPG outputs/work/replay_research/user_clarifications.md:197>)。此处是 F3 设计内容的补充，不新增实现步骤。

## 1. 事件怎样分类

分类只解决主持怎样取用资料，不是新增世界书类型。一个重大事件可以包含相互依赖的数个动作；只把会影响选择、资源、消息或重要人物处境的变化入账，不给每句对话建立节点。

| 分类 | 用法 | 本团例子 |
|---|---|---|
| 已完成前史 | 作为 T0 已成立事实；不再等待触发，不因新路线取消 | 高塔受魔物、魔兽双潮冲击，白魔在边关失守时脱逃 |
| 持续背景 | 保留习俗、关系、目标与活动方向；具体行动另按时期与条件判断 | 帝与哈克为兄弟；飘零祭习俗；墓地的非敌意调查 |
| 自主行动 | 根据行动者已有目标、资源、时间与消息推进，不要求 PC 接任务 | 相关军令、调查及势力行动；不能因御临风拒绝侦察而整体消失 |
| 条件互动 | 参与者的接触、报告、承诺或实际动作成立后处理 | 向某军官报信、右近收到军情后的核查 |
| 远期作者资料 | 保留因果索引，当前阶段不载入；将来相关时再取最小片段 | 秘境取石争议；不成为入帝都的命定终点 |

## 2. 状态与推进条件

事件只维护一个简短状态及其依据，必要时为其中不同动作分别记状态。例如“军令已下”和“御临风未接受侦察”可以同时成立，不能用后一项把前一项倒退。

| `status` | 含义 |
|---|---|
| `completed_pre_t0` | 已完成的前史；后果可继续存在，但不重新执行 |
| `background` | 关系、惯例或行动方向；不等于具体某次行动已经完成 |
| `waiting_conditions` | 某个具体动作尚缺已知必要条件；必须写明缺哪一项 |
| `active` | 本分支中有依据确认已经启动，按实际进展继续 |
| `blocked` | 已启动行动被具体障碍阻断；记障碍与可能解除条件 |
| `resolved` | 本分支实际有结果；记录发生了什么，不套原线结果 |
| `cancelled` | 有依据确认已放弃或失去实施条件；不能只因 PC 离开就取消 |
| `dormant` | 当前阶段不需载入的作者资料；不是“世界中被冻结直到 PC 来到” |

“资料未说明”不是 `waiting_conditions` 的同义词。能确定某行动尚未开始，才写尚未开始；只是不知医馆何时关闭，应写 `uncertain` 的时间边界，不能写成“等御临风走访才关闭”。已经成立的前史不因人物尚未知晓而回到待触发状态。

每次推进只看四件事：谁在做什么；依哪条已证目标或现场处境；哪些必要条件已成立；新选择实际改变了什么。条件成立后就推进，不另设每个节点都请用户批准的手续。条件不全时先区分缺的是事实、当前信息还是尚未执行的动作。记录 `confirmed`、`uncertain`、`rumor`、`character_belief` 时，标签描述证据地位；“条件已满足”另写，不能混在一个真假字段里。

只重判受到新选择影响的部分。原线两阵被毁触及七曜石后手的原线归因；新分支未毁阵便不能沿用该归因，但军令和其他独立行动仍按自身条件推进。[ECAP_002](<C:/Users/pit/.codex/worktrees/yulinfeng-tavern-plan/TRPG outputs/work/replay_research/event_causality_capital.jsonl:2>) 原结果是查证材料，不是达成目标，也不通过替身、巧合或补发奖励恢复原结局。

## 3. 时间与消息传播

世界内时间随实际行动推进。短暂观察、长谈、赶路、休息各有实际跨度；聊天轮数、用户离线时间、检索次数都不是剧情时钟。用“仍在城门前”“该场交谈后”“次晨”等来源或本分支已支持的相对锚即可，不必补全年月历。来源只支持“大约”或报告时点时，保留那个精度。

每轮无需遍历全世界。普通场内交互只更新直接相关动作；切场景、明确等待、长途旅行及重大消息到达时，再检查当前阶段已启动的少数外部行动。用户等待一夜，足以让有成立条件的行动继续；主持应在下一选择点或重要外界变化处呈现，而不是为了凑时间任意制造危机。没有独立变化的依据时，允许平静过渡。

一条消息分开记“世界中发生”“发出或进入渠道”“收到”“接收者相信多少”。有信使或通信工具不等于已发送，命令下达不等于执行完成。消息在传闻渠道流传仍是 `rumor`；可信人物转述也不自动核实其推论。说谎、猜测和内心活动仍属说话者。

最小消息记录为：内容及证据地位、发送者或见证者、渠道、当前阶段（未发／在途／已收／中断／未明）、接收者及截至哪条本分支消息。只在时限会影响行动时记录时限；未知渠道或传播速度不填成瞬时，也不私设永远无法传回。已证跨线报道只给相对先后，不能拼成精确同步日历。[事件总览](<C:/Users/pit/.codex/worktrees/yulinfeng-tavern-plan/TRPG outputs/work/replay_research/event_causality_overview.md:29>)、[ESIDE_006](<C:/Users/pit/.codex/worktrees/yulinfeng-tavern-plan/TRPG outputs/work/replay_research/event_causality_sides.jsonl:6>)

## 4. 世界真相和人物获知

事件种子的 `world_facts` 保存作者所掌握的有来源事实，并标明适用时期。`knowledge` 只记录明确获得的知识、渠道或记忆边界。未记录某人知情，表示不能凭这份种子授予他知识，不表示此人被证明无知或失忆。幕后资料仅在裁定需要时载入必要部分，不用全知旁白先向玩家揭示。

T0 的御临风能报告边关被破；不能初始化成全无前史记忆，也不能把原线较晚恢复的全部内情提前恢复。[OPENR_007](<C:/Users/pit/.codex/worktrees/yulinfeng-tavern-plan/TRPG outputs/work/replay_research/opening_state_consolidated.md:43>) 悠悠认为完成凌迟托付就是入都后等待咒术爆发，这项本人理解不得改写成咒术真实机理或其他人已知的计划。[UCL_20261003_010](<C:/Users/pit/.codex/worktrees/yulinfeng-tavern-plan/TRPG outputs/work/replay_research/user_clarifications.md:253>)

`author_only: true` 是资料使用标签，不是技术隔离。若把整个种子 JSON 送进同一模型请求，模型仍看得到里面的秘密。默认只取当前必要事实、行动条件与知情边界；完整未来史料与梦境内容不进 T0 主持包。未实现的加载器、自动计时器或存档功能不能靠字段名称假定已经存在。

## 6. 本轮主持怎样操作

1. 读玩家实际声明，确认这是动作、尝试、问题还是桌外讨论；不补写御临风同意、报信、追赶或成长。
2. 读取当前场景及有关种子的最小片段，核对适用时期；先处理现场动作、NPC 反应和资源变化。
3. 依据本轮真正经过的世界内时间、消息及条件变化，推进相关自主行动。没有时间跨度或有效消息，不凭回复轮数推进远方。
4. 只呈现御临风当前可感知、实际收到或能由已知事实判断的变化；到重要选择处停止。
5. 在本轮保留后记录必要增量：事件状态变化及原因、已发生结果、消息获得、耗用与未决条件。未实行的计划、重生成弃稿和候选结果不入账。
6. 场景收束或关键变化时整理短检查点，标明分支及截至消息。下一场读取检查点加其后保留聊天；重生成或分叉时恢复相应检查点，不叠加弃稿结算。

这些是主持操作规则。字段本身不会使模型在后台持续计时、自动写盘、随聊天删除正确回滚或模拟未加载人物。本轮只提供内容规范；使用酒馆现有聊天、分支／检查点和摘要位置保存并接续。关键变化时整理一次短摘要即可，不要求每轮手填全部事件，也不意味着酒馆原生聊天不能保存。

## 7. 真实未知怎样继续玩

不影响当前动作的未知，保持未知并继续。比如军官是否被催眠无需在一次问路中先判定；医馆案起时未明也不阻止角色前往查看。新分支只能从实际可见情况、接触和查证继续，不能把随口编出的旧案动机变成原团事实。[OPENR 未知边界](<C:/Users/pit/.codex/worktrees/yulinfeng-tavern-plan/TRPG outputs/work/replay_research/opening_state_consolidated.md:69>)

会影响眼前成败的未知，先做最小定点查证；仍无证据时，区分两种情况。若是历史真相或永久设定缺口，保留未解，只让已有证据支持的局部行动和反应发生，必要时用一句桌外说明指出缺口。若是本分支尚未发生的具体战术与后果，依已知目标、资源、规则和现场条件作新分支裁定并记录，不能把这项裁定追认作旧正典。只有缺失规则或数值确实决定重大成败时，才提出一个局部裁定选择；不是把每次未知都变成审批。

未知数量不默认为 0、满额或无限；未知期限不默认为“永不发生”或“下一轮必发”；未知身份不通过原型人物表自动认人。对未完成的远方任务，可保留“尚无完成记录”，不能写成任务已失败或永远不回报。
